## 五、AI问题根因分析

### 1. 策划案阅读不够深入

**表现**：只理解了功能概述，没有深入理解具体规则和边界

**证据**：
- 策划案明确写了"技能等级=min(原英雄技能等级, 槽位等级)"，但AI只验证了4个简单场景
- 策划案列出了所有"不可共享"场景，但AI只验证了部分

### 2. 没有理解大型系统的复杂度

**表现**：用中小型功能的用例数量来覆盖大型系统

**证据**：
- 人工用例按"模块划分"清晰分为：新英雄常规(20%)、专属技能(10%)、英雄共享(40%)、派兵表现(20%)、副本(10%)
- AI把所有内容混在一起，没有模块化思维

### 3. 战斗场景严重忽视

**表现**：几乎没有战斗相关验证

**证据**：
- 人工用例有约300条战斗相关用例，覆盖10+战斗场景
- AI只有6条基本出征用例

### 4. 缺乏"功能交叉"思维

**表现**：只验证单一功能，不考虑与其他系统的交互

**证据**：
- 红色英雄×背后灵、红色英雄×战车、红色英雄×竞技场等全部遗漏

### 5. 评审遗漏点意识缺失

**表现**：人工用例有32个评审遗漏点全部编号追踪，AI没有这个概念

## 六、改进方向

### 1. 大型系统必须模块化

```
第一步：根据策划案识别主要模块
第二步：每个模块估算用例数量
第三步：检查模块用例数量是否合理

示例：
- 新英雄常规：~200条（20%）
- 专属技能：~150条（10%）
- 英雄共享：~600条（40%）
- 派兵表现：~300条（20%）
- 副本验证：~150条（10%）
总计：~1400条
```

### 2. 战斗场景必须全覆盖

```
战斗场景清单（大型英雄系统必测）：
□ 野外pvp/pve
□ 攻击建筑驻防部队
□ 驻防中立建筑（联盟建筑/采集点/遗迹）
□ 城墙防守
□ 托管战斗
□ 集结发起/加入
□ 战车pvp/pve
□ 竞技场系列
□ 斗士远征
□ 各类副本
□ 特殊副本
```

### 3. 功能交叉必须验证

```
红色英雄系统交叉验证清单：
□ 红色英雄 × 背后灵
□ 红色英雄 × 战车
□ 红色英雄 × 竞技场
□ 红色英雄 × 托管
□ 红色英雄 × 派兵存档
□ 红色英雄 × 兵工厂驻扎
□ 红色英雄 × 皮肤
□ 红色英雄 × 战装
□ 红色英雄 × 深海试炼
```

### 4. 等级约束必须分段验证

```
当存在等级约束关系时：
□ A < B 情况
□ A = B 情况
□ A > B 情况
□ 升级A后仍 < B
□ 升级A后 = B
□ 升级A后 > B
□ A满级情况
□ B满级情况
□ A未解锁情况
```

### 5. 红点验证必须完整

```
红点验证清单：
□ 触发条件
□ 显示位置（多层级）
□ 消除条件
□ 重启客户端后状态
□ 重启服务器后状态
□ 跨UTC0点后状态
```
