## 二、核心设计模式

### 模式1：状态链式验证

**示例**：英雄从未获得到获得的完整状态链
```
未达到显示条件 → 达到显示条件未解锁 → 解锁获得 → 共享中 → 放弃共享
```

每个状态都要验证：
- 界面显示（模型、名称、等级、星级）
- 功能按钮状态（置灰/高亮）
- 操作限制（可/不可执行）

### 模式2：技能等级分段验证

```
| 检查点 | 技能等级<槽位等级 | 技能等级=槽位等级 | 技能等级>槽位等级 |
|--------|------------------|------------------|------------------|
| 颜色显示 | 绿色 | 白色 | 红色+向下箭头 |
| 实际生效 | 技能等级 | 技能/槽位等级 | 槽位等级 |
```

### 模式3：多入口一致性+交叉验证

```
英雄展示界面 → 查看共享信息栏
能力共享界面 → 查看共享技能模块
共享技能界面 → 查看槽位等级
派兵界面 → 查看详情模式
战报详情 → 查看技能显示

所有入口数据必须一致！
```

### 模式4：场景情况覆盖（遍历式）

```
新英雄部队战斗场景覆盖：
1、野外pvp战斗
2、野外pve战斗
3、攻击建筑驻防部队
4、驻防中立建筑（联盟建筑/采集点/遗迹等）
5、城墙防守
6、托管战斗
7、集结发起
8、集结加入
9、战车pvp/pve
10、各类副本（竞技场、斗士远征、gvg等）
```

### 模式5：条件组合验证

**共享场景覆盖**：
```
可共享情况：
- B正在城墙内驻扎并上锁
- B正在兵工厂内驻扎
- B正在副本里上阵

不可共享情况：
- B正在野外驻扎
- B正在建筑内（联盟建筑、遗迹、关卡、其他玩家主城内）驻扎
- B正在押镖/托管/采集
- B在围墙驻扎，主城正在被攻击
- A红色英雄在野外时尝试共享
```

### 模式6：生效等级取最小值验证

```
共享技能生效等级 = min(技能等级, 槽位等级)

验证场景：
- 升级槽位后依旧小于技能等级 → 生效数值刷新
- 升级槽位后等于技能等级 → 生效数值刷新
- 升级槽位后大于技能等级 → 生效数值不变
- 升级技能后依旧小于槽位等级 → 生效数值刷新
- 技能满级/槽位满级边界
```

### 模式7：战力来源分层验证

```
战力来源叠加：
- 基础战力（一星一级）
- 升级战力增加
- 升星战力增加
- 技能战力增加
- 天赋战力增加
- 双天赋技能战力增加
- 终极技能战力

关键验证点：
- 共享战力不会增加总战力
- 放弃共享后战力减少
- 切换共享英雄战力正确变化
```

## 三、用例设计技巧

### 1. "接上"连续操作

```
| YXGX_067 | 有额外掉落 | 1-4级装饰物检查 | 宝箱等级为1级 |
| YXGX_069 | | 接上，继续升级到5-9级 | 宝箱等级正确显示为2级 |
| YXGX_070 | | 检查已获得宝箱等级 | 已获得宝箱等级仍为1级，不会改变 |
```

**优点**：验证"已获得的状态不会因后续操作改变"

### 2. 编号规则规范

- **基础编号**：HSYX_001（模块前缀_序号）
- **评审补充**：LJZ_001（姓名拼音_序号）
- **新增修改**：ZY_001（姓名简拼_序号）

### 3. 预期结果+备注配合

```
| 预期结果 | 备注 |
|----------|------|
| 战力符合配置 | 1925 1921 |
| 升级所需碎片符合配置 | 1951 |
| 生效等级取最小值 | 技能生效等级取：min（技能等级，槽位等级）|
```

### 4. 二次确认弹窗全覆盖

```
1. 弹窗显示检查（标题、内容、按钮）
2. 点击取消 → 不执行操作
3. 点击关闭按钮 → 不执行操作
4. 点击确认 → 执行操作
5. 条件不足点击确认 → 报错提示
```

### 5. 特殊情况单独模块

```
特殊情况：
- A共享B，A不在城内切换共享C → 报错
- A共享B，B不在城内切换共享C → 报错
- A共享B，C不在城内切换共享C → 报错
- A驻扎围墙时放弃共享B → B能正常派出
```

## 四、大型系统用例设计要点

### 1. 功能交叉验证

```
红色英雄 × 背后灵：
- 背后灵助战无共享新英雄
- 背后灵助战共享新英雄
- 已共享背后灵助战
- 已助战背后灵共享
- 被助战+共享被助战英雄（复杂组合）
```

### 2. 派兵存档+状态变化

```
1. A共享B → 将A进行派兵存档
2. A切换共享C → 选中存档派出
预期：能够派出A英雄，共享的C英雄技能

1. A共享B → 将A进行派兵存档
2. A放弃B → 选中存档派出
预期：能够派出A英雄，不再享受共享buff
```

### 3. 红点状态详细验证

```
未共享红点：
- 英雄入口hud红点+1
- 英雄展示界面A卡片红点+1
- 英雄展示界面共享按钮显示无数值红点
- 能力分享界面共享按钮不显示红点

共享后：
- 以上红点全部-1或消失
```

### 4. 筛选联动验证

```
筛选-等级：A共享B(x级) → A按照x级排序
筛选-战斗力：A增加x共享战斗力 → A按照基础战力+x排序
筛选-天赋树类型：B天赋树类型a/b/c → 选a能筛出A、B
放弃共享后筛选：无法再筛出A
```

## 五、可复用的检查清单

### 大型系统必测项

1. **状态完整验证**：未解锁→解锁→使用中→切换→卸下
2. **多入口一致性**：所有能看到数据的入口都要验证
3. **条件组合覆盖**：可操作/不可操作的所有场景
4. **战斗场景遍历**：野外/建筑/副本/集结/战车
5. **战力来源分层**：每种战力来源单独验证
6. **红点状态联动**：触发/消除的完整链路
7. **存档状态变化**：存档后状态变化的影响
8. **特殊组合验证**：功能交叉的复杂场景

### 技能系统必测项

1. **等级分段验证**：<、=、> 三种情况
2. **生效等级取值规则**：min/max逻辑
3. **升级后立即生效验证**
4. **满级边界验证**
5. **多技能组合生效验证**
