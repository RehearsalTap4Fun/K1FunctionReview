## 一、核心设计原则（原文总结）

> **用例设计四原则**：
> 1. **描述/提炼准确**：给出明确的规则定义，后面直接沿用定义
> 2. **环环相扣**：尽量按测试顺序检查
> 3. **拆解再重组**：找到最合适的模块（简单的单规则验证完，再做组合）
> 4. **清晰引导**：无法完全做到第2/3点的，给出清晰的引导提示（参考哪里、哪里可以合并检查）

## 三、用例设计模式提炼

### 模式1：规则定义后沿用

**示例**：
- 定义"已解锁斗士"、"未解锁斗士"后，后续直接使用
- 定义"新皮肤"、"初始皮肤"后，全文统一术语

**作用**：
- 避免重复描述
- 保持用例一致性
- 便于阅读理解

### 模式2：先简后复（拆解再重组）

**执行顺序**：
```
1. 单规则验证（简单）
   ↓
2. 组合规则验证（复杂）
```

**示例**：
| 阶段 | 模块 | 说明 |
|------|------|------|
| 简单 | 单个使用-限时 | 单独验证限时皮肤道具效果 |
| 简单 | 单个使用-永久 | 单独验证永久皮肤道具效果 |
| 组合 | 组合使用 | 同个限时道具过期后/生效中连续使用 |
| 组合 | | 不同限时道具生效中连续使用 |
| 组合 | | 先限时再永久 / 先永久再限时 |

### 模式3：环环相扣（测试顺序）

**皮肤使用流程**：
```
获得道具 → 背包使用 → 激活皮肤 → 装备皮肤 → 返回界面 → 重进验证
```

**用例体现**：
```
| 步骤 | 预期结果 |
|------|----------|
| 点击使用道具 | 弹出使用成功tips |
| 进入涂装界面 | 新皮肤为已解锁未穿戴状态 |
| 检查界面变化 | 已拥有数量正确更新，图标点亮 |
| 点击新皮肤图标 | 正确切换，按钮变为"装备" |
| 点击装备按钮 | 图标变为绿色打钩，按钮变为"已装备" |
| 返回上一级 | 斗士列表头像变为新皮肤 |
| 重进涂装界面 | 保持新皮肤选择状态 |
```

### 模式4：引导提示

**用法示例**：

| 用例描述 | 引导提示 |
|----------|----------|
| 检查弹窗功能常规 | "与上方xx模块的预期一致" |
| 抽查上面的显示界面 | "对照【显示场景】模块" |
| 道具类型遍历 | "2种使用方式+3种道具任意组合抽查3种即可" |
| 检查限时时间内 | "新皮肤均可正常使用" |

**作用**：
- 减少重复描述
- 明确依赖关系
- 指导测试执行

### 模式5：维度矩阵覆盖

**场景覆盖维度**：

| 维度1（使用位置） | 维度2（角色类型） | 组合 |
|------------------|------------------|------|
| 主将 | 新皮肤 | 仅主将为新皮肤 |
| 副将 | 新皮肤 | 仅副将为新皮肤 |
| 主将+副将 | 新皮肤 | 主、副将均为新皮肤 |

**道具类型遍历**：

| 道具类型 | 使用方式 | 组合说明 |
|----------|----------|----------|
| 限时皮肤-n天 | 背包使用 | |
| 限时皮肤-m天 | 涂装界面激活 | 抽查3种组合即可 |
| 永久皮肤 | | |

### 模式6：状态转换覆盖

**皮肤状态机**：
```
未解锁 → 待激活 → 已激活未穿戴 → 已穿戴
                                    ↓
                              过期/手动切换
                                    ↓
                               恢复初始
```

**状态变化用例**：

| 场景 | 起始状态 | 结束状态 | 验证点 |
|------|----------|----------|--------|
| 从失效到生效 | 使用默认皮肤 | 激活并穿戴新皮肤 | 立即生效显示+buff |
| 从生效到失效 | 限时皮肤使用中 | 倒计时结束 | 立即恢复初始+buff失效 |
| 手动切换 | 新皮肤穿戴中 | 手动切回默认 | 正常切换+效果一致 |

### 模式7：三类资源验证

**皮肤显示验证分类**：

| 资源类型 | 场景示例 |
|----------|----------|
| 模型 | 斗士主界面、编队界面、大地图行军 |
| 头像列表 | 斗士列表、编队选择、队列列表 |
| 小头像 | 战报、集结详情、部队弹窗 |

**用例体现**：
```
| 步骤 | 预期结果 |
|------|----------|
| 有模型的场景 | 立即恢复到初始皮肤显示 |
| 有头像列表的场景 | 立即恢复到初始皮肤显示 |
| 有小头像的场景 | 立即恢复到初始皮肤显示 |
```

### 模式8：检查目的标注

**备注列使用**：

| 模块 | 检查目的标注 |
|------|--------------|
| 无新皮肤初始界面 | "基础的新增界面检查" |
| 基础切换选择 | "默认状态下的资源显示、切换检查" |
| 皮肤使用-背包 | "只检查'用'，不管'用什么'" |
| 道具类型遍历 | "检查'用什么'" |
| 多皮肤+buff | "多皮肤+buff实际效果组合检查" |
| 使用状态覆盖 | "检查会变化的" / "检查不变化的" |

## 六、关键设计技巧总结

### 1. 两条使用路径

| 路径 | 说明 | 按钮状态 |
|------|------|----------|
| 背包使用 | 先在背包使用道具 | 装备（绿色） |
| 涂装界面激活 | 拥有道具时直接在界面激活 | 激活（黄色+特效）→装备 |

### 2. 即时变化 vs 不变化

| 类型 | 场景 | 预期 |
|------|------|------|
| 变化 | 行军中/战斗中/集结中 | 均有正确的即时变化 |
| 不变化 | 变化前已产生的战报数据 | 不会有变化，仍为之前状态 |

### 3. 特殊机制覆盖（背后灵）

| 场景 | 覆盖点 |
|------|--------|
| 背后灵有新皮肤，不附身 | 与其他斗士效果一致 |
| 背后灵无新皮肤，附身新皮肤斗士 | 不影响新皮肤显示 |
| 背后灵有新皮肤，附身默认皮肤 | 背后灵头像显示新皮肤 |
| 背后灵有新皮肤，附身新皮肤 | 两者皮肤独立显示 |
| 附身过期-背后灵皮肤过期 | 不影响宿主 |
| 附身过期-宿主皮肤过期 | 不影响背后灵 |

## 七、用例编写最佳实践

### 模块命名规范

| 命名方式 | 示例 |
|----------|------|
| 功能+状态 | 无新皮肤初始界面、皮肤使用中状态变化 |
| 功能+场景 | 使用效果-显示场景、buff生效检查 |
| 动作+对象 | 皮肤获得、皮肤使用、皮肤失效检查 |

### 检查点命名规范

| 命名方式 | 示例 |
|----------|------|
| 区域+状态 | 涂装选择&属性展示区域 |
| 对象+动作 | 模型检查、切换选择 |
| 条件+结果 | 限时效果检查、组合buff验证 |

### 结果描述规范

| 模式 | 示例 |
|------|------|
| 正确+动词 | 正确显示、正确切换、正确刷新 |
| 状态变化 | 按钮变为"装备"、图标变为绿色打钩 |
| 引用对照 | 预期与上方一致、对照配置表 |
