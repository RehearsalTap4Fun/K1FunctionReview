## 用例编写模式分析

### 1. 检查点命名模式
- **入口类**: 入口、界面、弹窗
- **状态类**: 开启、显示、触发条件
- **操作类**: 单抽、10抽、购买、兑换、领取
- **验证类**: 配置验证、概率验证、到账验证
- **边界类**: 循环、特殊情况、中途打断

### 2. 预期结果编写模式
- **配置验证**: "符合配置"、"与配置一致"
- **UI验证**: "界面所有ui元素符合需求"
- **功能验证**: "能够正常xxx"、"实际到账正确"
- **状态验证**: "置灰显示，点击无响应"、"高亮显示"

### 3. 备注使用模式
- **配置表引用**: 2121、2124、2116、2011、2013
- **本地化标记**: 本地化
- **UX标记**: ux
- **补充说明**: 具体的测试注意事项

### 4. 模块合并规则
- 同一功能模块下，功能模块列只在第一行显示
- 同一检查点下，检查点列只在第一行显示
- 相同操作步骤产生多个预期结果时，操作步骤列只在第一行显示
