# 核心设计模式精华

> 本文档整合所有人工用例分析中提炼的核心设计模式，去除冗余和冲突，保留精华。

---

## 一、四大核心原则

### 1. 规则定义后沿用
给出明确定义后，后续直接使用，避免重复解释。
```
定义："新皮肤"=通过活动获得的皮肤，"初始皮肤"=系统默认皮肤
后续：验证新皮肤效果... 验证初始皮肤效果...
```

### 2. 环环相扣
按测试顺序检查，形成流程链。
```
获得 → 使用 → 激活 → 装备 → 验证效果
```

### 3. 拆解再重组
先验证简单规则，再验证组合规则。
```
单独验证A效果 → 单独验证B效果 → 验证A+B组合效果
```

### 4. 清晰引导
无法独立验证时，给出参考提示。
```
"与上方xx模块一致"、"抽查3种即可"、"表现同入口1一致"
```

## 二、五大通用设计模式

### 模式1：状态驱动验证

**核心思想**：以对象状态变化为主线组织用例

**状态类型**：
| 类型 | 示例状态 |
|------|----------|
| 解锁状态 | 未解锁 → 待激活 → 已激活 |
| 道具状态 | 未领取 → 已领取 → 已使用 → 用完 |
| 功能状态 | 未开启 → 开启中 → 已结束 |

**验证模式**：每个状态验证所有相关UI和操作
```
状态A：入口显示/弹窗显示/按钮状态/操作结果
状态B：入口显示/弹窗显示/按钮状态/操作结果
...
```

---

### 模式2：流程分支覆盖

**核心思想**：穷举使用流程的每个分支

**分支树模板**：
```
触发操作
├── 条件1满足
│   ├── 选择A → 结果A
│   └── 选择B → 结果B
└── 条件1不满足 → 结果C
```

**每个分支都要验证**：
- 正向路径（成功）
- 负向路径（失败/取消）
- 中断路径（超时/异常）

---

### 模式3：条件矩阵覆盖

**核心思想**：多维条件的组合验证

**矩阵模板**：
| 条件A\条件B | 满足 | 不满足 |
|------------|------|--------|
| 满足 | 场景1 | 场景2 |
| 不满足 | 场景3 | 场景4 |

**应用场景**：
- 权限 × 解锁状态
- 档位 × 券类型
- 时间 × 数量

---

### 模式4：边界时机验证

**核心思想**：在临界点验证系统行为

**边界类型**：
| 类型 | 示例 |
|------|------|
| 时间边界 | 活动结束前1秒操作、CD刚好结束时操作 |
| 数量边界 | 刚好用完、恰好达到阈值 |
| 状态边界 | 操作过程中状态变化 |

**验证要点**：
- 边界前一刻的行为
- 边界时刻的行为
- 边界后一刻的行为

---

### 模式5：多入口一致性

**核心思想**：不同入口操作结果应一致

**验证模板**：
```
入口1（基准）：完整验证
入口2：表现同入口1一致
入口3：表现同入口1一致
交叉验证：入口1操作后从入口2进入，数据一致
```

## 三、场景专用设计模式

### 技能/养成类

**等级分段验证**：
```
0-N级（基础）→ N+1-M级（效果1）→ M+1-K级（效果2）→ 满级（特殊效果）
```
- 每段验证：界面显示 + 效果生效 + 数值正确
- 同段简化："效果与上方一致，数值正确增加"

**Buff持续验证**：
```
第n回合（触发）→ n+1（持续）→ n+2（持续）→ n+M（消失）
```

---

### 商业化/券类

**使用流程**：
```
点击购买
├── 无券/不在范围 → 直接支付
└── 有券且在范围 → 使用弹窗
    ├── 使用 → 占用 → 支付
    └── 不使用 → 直接支付
```

**档位匹配**：
```
| 券类型 | 匹配档位 | 其他档位 |
|--------|----------|----------|
| 通用券 | 全部生效 | - |
| 指定档 | 仅匹配档 | 不生效 |
```

---

### 活动类

**跨期验证**：
```
当期活动 → 结束 → 回收/重置 → 下期活动 → 重新开始
```

**玩家分类验证**：
| 玩家类型 | 回收 | 下期状态 |
|----------|------|----------|
| 有剩余 | ✓ | 重置 |
| 无剩余 | ✗ | 重置 |
| 未参与 | ✗ | 初始 |

## 四、AI常见问题与改进（V12.1新增）

> 基于「科林探索装饰物礼包」AI生成用例 vs 人工用例对比分析

### 问题1：前提条件缺失

```
❌ AI写法：进入雷达界面 → 显示装饰物礼包入口
✅ 人工写法：新号解锁科林的探索功能，首次进入雷达界面 → 右上方新增一个装饰物礼包
```

**改进**：操作步骤必须包含前提条件（账号状态、功能解锁状态、数据状态）

### 问题2：界面检查缺乏层次

```
❌ AI写法：检查礼包弹窗 → 显示xxx / 显示yyy / 显示zzz
✅ 人工写法：
  查看界面布局：顶部区域 → 标题 / 关闭按钮
  左侧区域 → 模型 / 名称 / 描述 / 放大镜图标
  礼包主体区域 → 道具图标及数量 / 必含装饰物道具显示在首位
  底部区域 → 购买按钮 / 档位切换 / 限购次数
```

**改进**：界面检查按区域拆分，逐区域验证

### 问题3：业务逻辑理解不深

```
❌ AI遗漏：涂刷道具是宝箱掉落的前提条件
✅ 人工验证：
  - 无额外掉落：未使用涂刷道具时 → 不显示宝箱
  - 有额外掉落：已使用涂刷道具 → 显示宝箱
  - 涂刷道具失效：等待失效后 → 不再掉落
```

**改进**：理清条件依赖链，每个节点都要验证（不满足/刚满足/失效）

### 问题4：边界场景不完整

```
❌ AI写法：跨天重置 → 每日次数重置
✅ 人工写法：
  当天未达上限，UTC0点后 → 掉落次数清零
  当天已达上限，UTC0点后 → 掉落次数清零
  再次达到上限 → 上限与当前等级一致
```

**改进**：边界场景要区分"之前状态"和"之后状态"

### 问题5：配置验证不具体

```
❌ AI写法：与配置一致 | 2148
✅ 人工写法：与配置一致 | 2148 A_ARR_BUFF
```

**改进**：标注具体字段名，便于对照验证

### 问题6：买完后入口行为遗漏

```
❌ AI遗漏：买完所有礼包后入口的行为
✅ 人工验证：
  重进雷达界面 → 礼包图标仍显示
  点击礼包图标 → 跳转至外观雷达装饰物对应界面
```

**改进**：礼包买完后入口的可能行为都要验证

### 问题7：弹窗关闭方式遗漏

```
❌ AI遗漏：只验证关闭按钮
✅ 人工验证：
  - 点击道具图标 → 显示描述气泡
  - 点击弹窗内空白 → 气泡消失
  - 点击弹窗外任意位置 → 关闭弹窗返回上一界面
  - 点击关闭按钮 → 关闭弹窗
```

**改进**：弹窗的所有关闭方式都要验证

### 问题8：遗漏"接上"连续操作验证

```
❌ AI写法：单独验证每个等级
✅ 人工写法：
  1-4级装饰物 → 宝箱等级为1级
  接上，升级到5-9级 → 宝箱等级变为2级
  检查已获得宝箱 → 已获得宝箱等级仍为1级，不会改变
```

**改进**：验证"已获得的道具状态不会因后续操作改变"

### 问题9：任务类型组合验证遗漏

```
❌ AI写法：只验证次数消耗
✅ 人工写法：
  掉落上限=n，当日完成：
  - 第n-1个任务，类型A → 正确掉落
  - 第n个任务，类型B → 正确掉落
  - 第n+1个任务 → 不掉落
  - 升级后上限增加 → 继续任务类型C → 正确掉落
  - 再次达到新上限 → 不掉落
```

**改进**：多维组合验证（任务类型×掉落上限×升级）

### 问题10：装饰物多入口、多状态遗漏

```
❌ AI写法：只验证已解锁后的一个入口
✅ 人工写法：
  【未解锁状态】
  - 建造界面 → 置暗未解锁状态 / tips描述正确
  【已解锁状态】
  - 建造入口 → 红点显示 / 已解锁可建造
  - 外观界面 → 图标模型正确 / 白天夜晚效果 / 所有等级模型一致
```

**改进**：多入口×多状态的组合验证

### 问题11：背包道具分类验证不全

```
❌ AI写法：只验证宝箱使用
✅ 人工写法：
  装饰物道具 → 在其他分页 / 不显示使用按钮
  粉刷道具 → 在其他分页 / 显示使用按钮
  随机宝箱 → 在其他分页 / 宝箱等级显示 / 显示使用按钮
```

**改进**：每种道具分别验证分页位置、使用按钮状态

### 问题12：跨服KVK场景完全遗漏

```
❌ AI遗漏：跨服KVK场景
✅ 人工写法：
  原服准备数据 → 进入KVK服 → 数据与原服一致
  KVK服功能操作 → 各功能正常
  返回原服 → 数据与KVK服一致
```

**改进**：涉及跨服功能必须验证KVK场景

### 问题13：老版本+数据兼容完全遗漏

```
❌ AI遗漏：版本兼容场景
✅ 人工写法：
  老包新服 → 不显示新功能
  新包新服 → 相关功能均正确出现
```

**改进**：新功能必须验证版本兼容

### 问题14：异常场景描述不完整

```
❌ AI写法：切后台 → 数据同步正确
✅ 人工写法：
  在进行【礼包购买/装饰物升级/涂刷/宝箱开启】操作时：
  - home键退出（未掉线）→ 返回数据正常
  - home键退出（已掉线）→ 返回数据正常
  - 弱网环境 → 可正常操作
```

**改进**：具体操作场景+未掉线/已掉线+弱网环境

### 问题15：文化局风险验证完全遗漏

```
❌ AI遗漏：国服文化局风险验证
✅ 人工写法：
  敏感词检查 → 无"随机、几率、概率、抽奖、gacha"等字样
  gacha行为验证 → 无直接使用宝石gacha / 道具gacha有限购
  概率公布 → 游戏内或外部链接有公布概率
```

**改进**：国服必须验证文化局风险

### 问题16：用户体验检查点过于笼统

```
❌ AI写法：界面布局 → 元素显示正常无遮挡
✅ 人工写法：
  数值合理性 → 解锁时间匹配 / 档位连续无断层 / 奖励递增合理
  操作合理性 → 文本对齐统一 / 确定取消按钮位置统一
  滑动体验 → 手动滑动范围正常 / 自动滑动定位正常
```

**改进**：拆分更细致的检查点

### 问题17：本地化检查不够细致

```
❌ AI写法：所有文本正确翻译 / 无文本截断
✅ 人工写法：
  - 排版正确（换行、行间距）
  - 语义清晰无歧义
  - 道具/资源有交代来源和用途
  - 英语文本标题、按钮需全大写
  - 国服单独检查
```

**改进**：增加排版、语义、大写规范等检查点

### 问题18：兼容性检查系统版本覆盖不全

```
❌ AI写法：iOS高/中/低端，Android高/中/低端（6条）
✅ 人工写法：
  - FW项目分辨率兼容（>2:1长屏、<4:3窄屏）
  - 特殊屏幕（三星、水滴、挖孔、刘海、曲面屏）
  - Android 6-14（9个版本）+ 鸿蒙
  - iOS 10-18（9个版本）
  - Android虚拟返回键
```

**改进**：完整系统版本列表+特殊屏幕类型

## 五、大型系统设计模式（V12.2新增）

> 基于「红色英雄系统」人工用例分析（1498条）

### 模式1：生效等级取最小值验证

**核心思想**：当存在多个等级约束时，实际生效取最小值

```
共享技能生效等级 = min(技能等级, 槽位等级)

| 场景 | 技能等级 | 槽位等级 | 实际生效 | 显示颜色 |
|------|:--------:|:--------:|:--------:|:--------:|
| 技能<槽位 | 3 | 5 | 3 | 绿色 |
| 技能=槽位 | 5 | 5 | 5 | 白色 |
| 技能>槽位 | 7 | 5 | 5 | 红色+↓ |
```

### 模式2：功能交叉验证

**核心思想**：两个功能同时存在时的互斥与兼容

```
红色英雄 × 背后灵：
- 背后灵助战无共享新英雄 → 正常助战
- 已共享背后灵助战 → 列表不显示
- 已助战背后灵共享 → 报错"参与助战中"
- 被助战+共享被助战英雄 → 复杂组合验证
```

### 模式3：战力来源分层验证

**核心思想**：战力由多个来源叠加，需分层验证

```
战力来源：
- 基础战力（一星一级）
- 升级战力
- 升星战力
- 技能战力
- 天赋战力
- 终极技能战力

关键验证：
- 共享战力不增加总战力
- 放弃共享后战力减少
- 切换共享英雄战力正确变化
```

### 模式4：存档状态变化验证

**核心思想**：存档后状态变化对存档使用的影响

```
1. A共享B → 将A进行派兵存档
2. A切换共享C → 选中存档派出
预期：派出A英雄，使用C英雄技能（非存档时的B）

1. A共享B → 将A进行派兵存档
2. A放弃B → 选中存档派出
预期：派出A英雄，不再享受共享buff
```

### 模式5：场景全覆盖遍历

**核心思想**：新功能必须覆盖所有战斗场景

```
战斗场景清单：
1. 野外pvp/pve
2. 攻击建筑驻防部队
3. 驻防中立建筑（联盟建筑/采集点/遗迹）
4. 城墙防守
5. 托管战斗
6. 集结发起/加入
7. 战车pvp/pve
8. 各类副本（竞技场、斗士远征、gvg）
9. 特殊副本（王者之地、AC战场、机甲战场）
```

### 模式6：红点状态联动验证

**核心思想**：红点的触发、消除、联动必须完整验证

```
未共享红点链路：
- 英雄入口hud红点+1
- 英雄展示界面A卡片红点+1
- 共享按钮显示无数值红点

共享后链路：
- 以上红点全部-1或消失

重启/跨天验证：
- 重启客户端/服务器后红点状态不变
- 跨UTC0点后红点状态不变
```

## 六、精简原则

### 1. 遍历简化
- 选取典型：第一档 + 中间档 + 最后档
- 同类简化："表现均与上方一致"

### 2. 场景复用
- 战斗场景列表：野外PVP/PVE、副本、竞技场、特殊模式
- 简化写法："结果与上方一致"

### 3. 配置关联
- 涉及数值：标注配置表ID + 字段名
- 涉及文本：标注"本地化"
