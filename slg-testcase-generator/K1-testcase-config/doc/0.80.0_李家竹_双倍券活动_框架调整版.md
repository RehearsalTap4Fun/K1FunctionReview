## 二、用例设计分析

### 1. 道具状态驱动的验证模式

**道具状态流转**：
```
未领取 → 已领取（可用）→ 已占用（支付中）→ 已使用/用完 → 活动结束（回收）
```

**每状态验证点**：

| 状态 | 入口1(HUD) | 入口2(付费墙) | 弹窗 | 页签标签 | 购买按钮 |
|------|------------|---------------|------|----------|----------|
| 未领取 | 显示+倒计时 | 可领取特效 | 领取按钮 | 无标签 | 无标签 |
| 已领取 | 显示+倒计时 | 无特效+倒计时 | 前往按钮 | 双倍标签 | 双倍标签 |
| 用完 | 显示+倒计时 | 无特效+倒计时 | 数量0 | 无标签 | 无标签 |
| 活动结束 | 消失 | 消失 | - | 无标签 | 无标签 |

### 2. 多入口一致性验证

**入口对比**：
| 操作 | 入口1(主界面HUD) | 入口2(付费墙右上角) |
|------|------------------|---------------------|
| 领取双倍券 | 可以 | 可以 |
| 打开弹窗 | 可以 | 可以(领取前)/不可以(领取后) |
| 查看状态 | 弹窗内显示 | 入口特效/倒计时 |

### 3. 使用流程的分支验证

**购买流程**：
```
点击购买按钮
    ├── 无双倍券 → 直接拉起支付
    └── 有双倍券
        ├── 礼包在白名单 → 弹出使用弹窗
        │   ├── 选择"立即使用" → 占用券 → 拉起支付
        │   │   ├── 取消支付 → 券被占用5min
        │   │   └── 确认支付 → 获得双倍 → 券数量-1
        │   └── 选择"下次使用" → 拉起支付（单倍）
        └── 礼包不在白名单 → 直接拉起支付
```

### 4. 档位条件匹配验证

**固定档位双倍券**：
```
| 道具类型 | 生效档位 | 其他档位 |
|----------|----------|----------|
| 道具1 | 所有档位 | - |
| 道具2 | 仅4.99 | 不生效 |
| 道具3 | 仅9.99 | 不生效 |
| 道具4 | 仅19.99 | 不生效 |
| 道具5 | 仅49.99 | 不生效 |
| 道具6 | 仅99.99 | 不生效 |
```

**验证点**：
- 只有匹配档位的购买按钮显示双倍标签
- 购买匹配档位可获得双倍
- 购买非匹配档位不获得双倍

### 5. 多档双倍券优先级验证

**优先级规则**：道具1 > 道具2 > ... > 道具6

**验证场景**：
- 同时拥有a档和b档双倍券，显示a档数量
- 使用完a档后，切换显示b档数量
- 优先使用高优先级档位

### 6. 占用与释放机制验证

**占用机制**：
- 选择"立即使用"后，券被临时占用
- 取消支付后，券仍被占用5分钟
- 5分钟后可重新使用

**验证场景**：
```
仅剩1张券 → 选择使用 → 取消支付
    ├── 立即再次购买 → 不弹使用弹窗（券被占用）
    └── 等待5min后购买 → 弹出使用弹窗（券释放）
```

## 三、用例设计技巧

### 1. 状态矩阵覆盖

```
| 场景\状态 | 未领取 | 已领取 | 用完 | 活动结束 |
|-----------|--------|--------|------|----------|
| 入口1显示 | ✓ | ✓ | ✓ | ✓ |
| 入口2显示 | ✓ | ✓ | ✓ | ✓ |
| 弹窗显示 | ✓ | ✓ | ✓ | - |
| 页签标签 | ✓ | ✓ | ✓ | ✓ |
| 购买按钮 | ✓ | ✓ | ✓ | ✓ |
| 购买结果 | ✓ | ✓ | ✓ | ✓ |
```

### 2. 档位组合覆盖

```
| 场景 | 第一档 | 中间档 | 最后档 |
|------|--------|--------|--------|
| 通用双倍券 | ✓(生效) | ✓(生效) | ✓(生效) |
| 指定档双倍券 | 看匹配 | 看匹配 | 看匹配 |
| 无双倍券 | ✓(单倍) | ✓(单倍) | ✓(单倍) |
```

### 3. 回收与跨期验证

```
当期活动 → 结束 → 未用完的券 → 回收邮件
                              ↓
                        下期活动 → 重新领取 → 数量重置
```

## 六、用例框架特点

### 框架调整版特色

1. **模块化组织**：按功能流程组织，而非按页面
2. **状态驱动**：以道具状态变化为主线
3. **覆盖矩阵**：档位×状态×场景的组合覆盖
4. **通用模板**：用户体验、本地化、兼容性等通用模块

### 用例编写风格

```
| 编号 | 功能模块 | 检查点 | 操作步骤 | 预期结果 | 备注 |
| SBJ_001 | 活动开启前检查 | HUD | 不开启双倍券活动，检查付费墙及常规活动界面 | 主界面不会显示双倍券活动入口 | |
```

- 操作步骤：明确前提条件 + 具体操作
- 预期结果：具体的UI/数据变化
- 备注：配置表、本地化标记
