# AI用例问题分析：科林探索装饰物礼包

**对比样本**：
- AI生成：162条
- 人工优化：187条（框架调整版）
- 差异：人工多25条（+15%）

---

## 一、核心差异总结

| 差异类型 | AI问题 | 人工做法 |
|----------|--------|----------|
| **前提条件缺失** | 直接写"进入雷达界面" | "新号解锁科林的探索功能，首次进入雷达界面" |
| **操作步骤模糊** | "检查礼包弹窗" | "查看界面布局：顶部区域"、"左侧区域"、"礼包主体区域"、"底部区域" |
| **预期结果笼统** | "显示礼包奖励内容" | "必含装饰物道具图标，显示在首位" + "其他道具与配置一致" |
| **业务逻辑遗漏** | 缺少涂刷道具使用条件 | "无额外掉落"场景：未使用涂刷道具时不显示宝箱 |
| **边界场景不足** | 只写"跨天重置" | "当天未达上限跨天" vs "当天已达上限跨天" 分开验证 |
| **配置验证缺失** | 只写"与配置一致" | 明确写出配置表ID和具体字段 |

## 二、详细问题分析

### 问题1：前提条件缺失

**AI写法** (RD_001)：
```
| 入口显示 | 进入雷达界面 | 显示装饰物礼包入口 |
```

**人工写法** (LDLB_001)：
```
| 入口 | 新号解锁科林的探索功能，首次进入雷达界面 | 右上方新增一个装饰物礼包 |
```

**问题**：AI没有说明"新号"、"首次进入"等前提条件，测试人员无法判断是什么状态下的测试

|       |           | 显示礼包价格 |
|       |           | 显示礼包奖励内容 |
|       |           | 显示ROI标签 |
```

**人工写法** (LDLB_005-LDLB_018)：
```
| 界面元素 | 查看界面布局：顶部区域 | 正确显示标题：装饰物限定礼包 |
|       |                    | 正确显示关闭按钮 |
|       | 左侧区域            | 正确显示装饰物名称 |
|       |                    | 正确显示装饰物描述 |
|       |                    | 正确显示装饰物模型 |

### 问题3：业务逻辑理解不深

**AI写法** (RD_077-RD_082)：
```
| 奖励预览 | 点击雷达任务查看奖励预览 | 显示额外随机宝箱 |
| 次数未尽 | 今日次数未用尽时 | 奖励预览显示宝箱 |
| 次数用尽 | 今日次数已用尽时 | 奖励预览不再显示宝箱 |
| 完成探索 | 完成雷达探索任务 | 宝箱和探索奖励一起获得 |
```

**人工写法** (LDLB_066-LDLB_075)：
```
| 无额外掉落 | 当前装饰物已解锁并建造，但未使用/拥有涂刷道具，点击任意雷达任务，查看奖励 | 不会有新增随机宝箱 |
| 有额外掉落 | 1. 雷达装饰物已解锁并建造，当前为1-4级
              2. 当前拥有涂刷道具并已使用
              3. 点击任意雷达任务，查看奖励 | 有新增随机宝箱显示，宝箱等级正确为1级 |
| | 接上，继续升级装饰物等级，等级为5-9级，检查雷达任务随机宝箱 | 宝箱等级正确显示为2级 |
| | 检查已获得宝箱等级 | 已获得宝箱等级仍为1级，不会发生改变 |
| 涂刷道具失效 | 1. 当前雷达装饰物已解锁并建造
                2. 涂刷道具拥有并已使用，道具正确生效
                3. 停留在雷达界面，等待涂刷道具失效
                4. 完成雷达任务 | 不再掉落随机宝箱 |
```

**问题**：
1. AI完全遗漏了"涂刷道具"是随机宝箱掉落的前提条件
2. AI没有验证"已获得宝箱等级不会随后续升级改变"这个重要逻辑
3. AI没有验证"涂刷道具失效后"的场景

## 三、问题根因分析

| 根因 | 表现 | 改进方向 |
|------|------|----------|
| **需求理解不深** | 遗漏涂刷道具是宝箱掉落前提 | 需要更仔细分析需求中的条件依赖关系 |
| **模板化套用** | 界面检查不够细致 | 按区域拆分界面，逐区域检查 |
| **边界意识不足** | 跨天只写一种情况 | 每个边界都要区分"之前"和"之后"两种状态 |
| **配置关联不够** | 只写表ID不写字段 | 标注具体字段名便于对照验证 |
| **前提条件缺失** | 直接写操作不写状态 | 操作步骤必须包含前提条件 |

## 四、改进措施

### 1. 操作步骤必须包含前提条件

```
❌ 错误：进入雷达界面
✅ 正确：新号解锁科林的探索功能，首次进入雷达界面
```

### 2. 界面检查按区域拆分

```
❌ 错误：检查礼包弹窗 → 显示xxx / 显示yyy / 显示zzz
✅ 正确：
  查看界面布局：顶部区域 → 标题 / 关闭按钮
  左侧区域 → 模型 / 名称 / 描述
  主体区域 → 道具列表 / 首位显示
  底部区域 → 购买按钮 / 档位切换 / 限购次数
```

### 3. 业务逻辑要理清条件依赖

```
宝箱掉落的条件链：
装饰物解锁 → 装饰物建造 → 涂刷道具使用 → 涂刷道具生效中 → 完成雷达任务 → 获得宝箱

每个节点都需要验证：
- 条件不满足时的表现
- 条件刚好满足时的表现
- 条件失效后的表现
```

### 4. 边界场景要区分状态

```
跨天重置：
- 当天未达上限 → 跨天后
- 当天已达上限 → 跨天后

掉落上限：
- 第n-1个任务（未达上限）
- 第n个任务（刚好达上限）
- 第n+1个任务（超过上限）
```

### 5. 配置验证要具体到字段

```
❌ 错误：与配置一致 | 2148
✅ 正确：与配置一致 | 2148 A_ARR_BUFF
```

### 6. 买完后的入口行为

```
礼包买完后入口的可能行为：
- 入口消失
- 入口保留但功能改变（跳转到其他界面）
- 入口保留且功能不变

需要明确验证具体是哪种
```
