## 一、核心设计模式

### 模式1：道具状态驱动验证

**适用于**：有使用次数、生命周期的道具/券类功能

**状态流转图**：
```
未领取 → 已领取（可用）→ 已占用（支付中）→ 已使用/用完 → 活动结束（回收）
```

**每状态验证矩阵**：

| UI位置 | 未领取 | 已领取 | 已占用 | 用完 | 活动结束 |
|--------|--------|--------|--------|------|----------|
| 入口1(HUD) | 显示+倒计时 | 显示+倒计时 | 显示+倒计时 | 显示+倒计时 | 消失 |
| 入口2(页内) | 可领取特效 | 无特效+倒计时 | 无特效+倒计时 | 无特效+倒计时 | 消失 |
| 弹窗数量 | 可领取数量 | 已拥有数量 | 已拥有数量 | 0 | - |
| 弹窗按钮 | 领取 | 前往 | 前往 | 前往 | - |
| 页签标签 | 无 | 双倍标签 | 双倍标签 | 无 | 无 |
| 购买按钮 | 无标签 | 双倍标签 | 双倍标签 | 无标签 | 无标签 |

### 模式2：使用流程分支验证

**适用于**：有条件触发、多选项的使用流程

**流程分支树**：
```
点击购买按钮
├── 无道具 → 直接拉起支付 → 单倍奖励
└── 有道具
    ├── 不在作用范围 → 直接拉起支付 → 单倍奖励
    └── 在作用范围 → 弹出使用弹窗
        ├── 选择"使用" → 道具占用 → 拉起支付
        │   ├── 取消支付 → 道具占用中（5min）→ 5min后释放
        │   └── 确认支付 → 双倍奖励 → 道具数量-1
        └── 选择"不使用" → 拉起支付 → 单倍奖励
```

### 模式3：条件匹配验证

**适用于**：有条件限制的功能（如档位、范围、时间）

**档位匹配矩阵**：
| 道具类型 | 4.99 | 9.99 | 19.99 | 49.99 | 99.99 |
|----------|:----:|:----:|:-----:|:-----:|:-----:|
| 通用券 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 4.99券 | ✓ | ✗ | ✗ | ✗ | ✗ |
| 9.99券 | ✗ | ✓ | ✗ | ✗ | ✗ |
| 19.99券 | ✗ | ✗ | ✓ | ✗ | ✗ |
| 49.99券 | ✗ | ✗ | ✗ | ✓ | ✗ |
| 99.99券 | ✗ | ✗ | ✗ | ✗ | ✓ |

**验证点**：
1. 匹配档位 → 显示标签 + 可使用 + 双倍奖励
2. 不匹配档位 → 无标签 + 不可使用 + 单倍奖励

### 模式4：优先级与互斥验证

**适用于**：多类型道具共存的场景

**优先级规则**：道具1 > 道具2 > 道具3 > 道具4 > 道具5 > 道具6

**验证场景**：
| 场景 | 显示 | 使用 | 消耗完后 |
|------|------|------|----------|
| 仅有A类 | A类数量 | 使用A类 | - |
| A类+B类 | A类数量 | 优先使用A类 | 切换显示B类 |
| 同时获得A+B | 仅保留A类效果 | - | - |

### 模式5：占用与释放机制验证

**适用于**：有临时锁定、超时释放的功能

**占用流程**：
```
选择使用 → 道具占用（锁定）→ 取消支付 → 保持占用（5min）→ 自动释放
                            └→ 确认支付 → 消耗道具
```

**验证场景**：
| 操作 | 占用状态 | 再次购买 |
|------|----------|----------|
| 选择使用后取消 | 占用中 | 不弹使用弹窗 |
| 5min后 | 释放 | 弹出使用弹窗 |
| 确认支付 | 消耗 | 数量-1 |

### 模式6：跨期/回收验证

**适用于**：有活动周期的功能

**验证流程**：
```
当期活动 → 结束 → 未用完道具 → 回收邮件（特定玩家）
                              ↓
                        下期活动 → 重新领取 → 数量重置
```

**玩家分类验证**：
| 玩家类型 | 回收邮件 | 下期状态 |
|----------|----------|----------|
| 未领取 | 无 | 可领取 |
| 已用完 | 无 | 可领取 |
| 有剩余 | 有（回收道具）| 可领取 |

## 二、用例设计技巧

### 1. 多入口一致性验证

**目的**：确保不同入口操作结果一致

**用法**：
```
| 入口 | 操作 | 预期 |
|------|------|------|
| 入口1(HUD) | 领取双倍券 | 领取成功 |
| 入口2(付费墙) | 领取双倍券 | 领取成功，同入口1 |
```

### 2. 档位遍历简化

**目的**：高效覆盖多档位场景

**用法**：
```
| 第一档(4.99) | 详细验证 |
| 中间档(19.99) | 详细验证 |
| 遍历其他档位 | 表现均同上方一致 |
```

### 3. 状态切换验证

**目的**：验证状态变化后的UI刷新

**用法**：
```
| 领取前状态 | 领取操作 | 领取后状态 |
| 领取按钮 | 点击领取 | 前往按钮 |
| 可领取特效 | | 特效消失 |
| 无双倍标签 | | 显示双倍标签 |
```

### 4. 边界时机验证

**目的**：验证活动边界时刻的行为

**用法**：
```
| 操作时机 | 预期 |
|----------|------|
| 活动结束前1秒点击使用 | 弹出使用弹窗 |
| 活动结束后确认支付 | 不双倍，只获单倍 |
| 活动结束后取消支付 | 道具立即回收 |
```

## 三、券类功能用例模板

### 1. 领取模块

```
| 模块 | 检查点 | 操作步骤 | 预期结果 |
|------|--------|----------|----------|
| 领取前 | 入口显示 | 检查主界面 | 显示领取入口+可领取特效 |
| | 弹窗显示 | 打开弹窗 | 显示可领取数量+领取按钮 |
| | 购买验证 | 点击购买 | 不弹使用弹窗，不双倍 |
| 领取 | 入口1领取 | 点击主界面入口领取 | 领取成功 |
| | 入口2领取 | 点击页面内入口领取 | 同入口1 |
| 领取后 | 入口显示 | 检查主界面 | 特效消失+显示倒计时 |
| | 弹窗显示 | 打开弹窗 | 显示已拥有数量+前往按钮 |
| | 标签显示 | 检查页签/按钮 | 显示双倍标签 |
```

### 2. 使用模块

```
| 模块 | 检查点 | 操作步骤 | 预期结果 |
|------|--------|----------|----------|
| 使用弹窗 | 触发 | 点击作用范围内礼包购买 | 弹出使用弹窗 |
| | 不触发 | 点击作用范围外礼包购买 | 不弹窗，直接支付 |
| 选择使用 | 取消支付 | 使用后取消 | 道具被占用 |
| | 确认支付 | 使用后确认 | 双倍奖励，数量-1 |
| 选择不使用 | 确认支付 | 不使用后确认 | 单倍奖励，数量不变 |
| 占用释放 | 5min内 | 再次点击购买 | 不弹使用弹窗 |
| | 5min后 | 再次点击购买 | 弹出使用弹窗 |
```

### 3. 档位匹配模块

```
| 模块 | 检查点 | 操作步骤 | 预期结果 |
|------|--------|----------|----------|
| 指定档位券 | 匹配档位 | 购买指定档位礼包 | 显示标签，可使用，双倍 |
| | 非匹配档位 | 购买其他档位礼包 | 无标签，不可使用，单倍 |
| | 档位切换 | 切换至下一档位 | 标签消失（如非匹配）|
| 多类型共存 | 显示优先 | 同时拥有A类+B类 | 显示A类数量 |
| | 使用优先 | 购买礼包 | 优先使用A类 |
| | 消耗完切换 | 用完A类 | 切换显示B类 |
```

### 4. 活动结束模块

```
| 模块 | 检查点 | 操作步骤 | 预期结果 |
|------|--------|----------|----------|
| 结束后显示 | 入口 | 检查主界面 | 入口消失 |
| | 页签标签 | 检查付费墙 | 标签消失 |
| | 购买按钮 | 检查购买 | 不弹使用弹窗 |
| 回收 | 有剩余 | 活动结束 | 收到回收邮件 |
| | 无剩余 | 活动结束 | 不收邮件 |
| | 未领取 | 活动结束 | 不收邮件 |
| 下期 | 进度重置 | 新一期开启 | 重新可领取 |
| | 数量重置 | 领取新券 | 数量=新期投放数 |
```

## 四、关键学习点总结

1. **状态驱动思维**：以道具/功能状态为主线组织用例
2. **条件匹配覆盖**：档位×范围×时间的组合验证
3. **分支流程覆盖**：使用流程的每个分支都要验证
4. **占用释放机制**：临时锁定、超时释放的边界验证
5. **多类型优先级**：优先级、互斥、切换的验证
6. **跨期回收验证**：活动周期结束后的数据处理
7. **多入口一致性**：不同入口操作结果应一致
