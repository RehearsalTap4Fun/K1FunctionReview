## 二、用例思路核心模式

### 模式1：流程覆盖 + 采用简单情况过流程

**用例思路列标注**：
> "采用其中一种简单的情况，过一遍流程"

**应用场景**：回收流程的第一阶段，用最简单的条件（拥有任意卡册一种卡片A，数量≥2）完整走一遍核心流程。

**关键点**：
- 先用简单场景验证主流程通畅
- 后续再覆盖复杂边界条件

### 模式2：条件分层验证

**回收池情况检查**：

| 条件 | 预期结果 |
|------|----------|
| 没有任何卡片 | 显示"无卡片 当前暂无可回收的卡片" |
| 同一卡册A卡1张 | 不显示（不可回收） |
| 同一卡册A卡n张，n=2 | 展示A卡，可回收数量1张 |
| 同一卡册A卡n张，n>2 | 展示A卡，叠加显示，可回收数量n-1张 |
| 同一卡册A卡n张，n>100 | A卡正确显示（大数值边界） |

**用例思路列标注**：
> "交待可回收的逻辑、做单规则验证"

**关键点**：
- 从"不可回收"到"可回收"的临界值（1张 vs 2张）
- 数量梯度覆盖：n=2（最小可回收）、n>2（正常）、n>100（大数值）

### 模式3：组合覆盖

**多卡多册场景**：

| 场景 | 检查点 |
|------|--------|
| 同一卡册多张卡 | 正确展示、回收数量、排序 |
| 不同卡册多张卡 | 所有卡片及数量均正确显示 |
| 卡片种类超过5 | 一排最多显示5个，多的换行 |
| 卡片种类超过10 | 回收卡区域可以正常左右滑动 |

### 模式4：操作边界验证

**选择操作边界**：

| 操作 | 场景 | 预期 |
|------|------|------|
| 单选仅1张 | 点击±按钮 | 无响应 |
| 单选多张 | 点击±至上下限 | 增减正确，到限后无响应 |
| 取消勾选 | 再次点击已勾选 | 取消勾选，±UI消失 |
| 多次重复操作 | 勾选/取消多次 | 操作正常，界面实时刷新 |

**输入框边界**：

| 输入类型 | 预期 |
|----------|------|
| 正确数字（上下限之间） | 可正常输入并保存 |
| 输入0 | 无法正常输入 |
| 超过上限的数字 | 无法正常输入 |
| 负数、小数 | 无法正常输入 |
| 空、空格 | 无法正常输入 |
| 特殊符号、表情 | 无法正常输入 |

### 模式5：一键操作验证

**一键全选状态覆盖**：

| 前置状态 | 操作 | 预期 |
|----------|------|------|
| 未勾选任何卡片 | 一键全选 | 所有卡片勾选，选择最大数量 |
| 手动勾选部分，不修改数量 | 一键全选 | 全部勾选，最大数量 |
| 手动勾选全部，随机修改数量 | 一键全选 | 全部恢复最大数量 |
| 一键全选后 | 一键取消 | 全部恢复未勾选，价格归0 |
| 一键全选后 | 手动取消任意 | 一键勾选按钮状态变化 |
| 一键全选后 | 修改任意数量 | 价格正确更新 |

### 模式6：回收结果遍历覆盖

**情况覆盖表**：

| 场景 | 验证点 |
|------|--------|
| 单卡多张，回收部分 | 单价对照配置，总价计算正确 |
| 多卡多张，把任意单卡回收完 | 回收池刷新正确 |
| 多卡多张，任选部分种类回收 | 剩余卡片排序正确 |
| 分别回收完首位/中间/末位卡片 | 位置相关逻辑正确 |
| 卡片种类超一页，回收最末位 | 滑动后的卡片回收正确 |
| 所有品质遍历 | 各品质卡片回收正确 |
| 全部回收完 | 回收池显示无卡片 |

## 三、用例设计关键技巧

### 1. 配置关联标注

**用例思路列标注**：
> "交待单卡回收对照的配置"

**应用**：在回收价格验证时，标注需要对照的配置表。

### 2. 参照已有功能

用例中多处提到"表现同上方一致"、"预期与上方一致"，减少重复描述，提高效率。

### 3. 状态变化验证

每次操作后验证：
- 勾选框状态变化
- 数量UI显示/消失
- 价格实时刷新
- 按钮状态变化

### 4. 失败用例标注

用例中F（未通过）的标注：
- GCLB_050：输入非正常数字（负数、小数）
- GCLB_060：一键勾选按钮状态变化

这些是需要特别关注的边界情况。

## 四、回收功能用例模板总结

### 通用结构

```
1. 回收流程（主流程）
   - 入口验证
   - 界面固定元素验证
   - 卡片展示验证
   - 选择操作验证
   - 回收确认验证
   - 回收结果验证

2. 回收池情况（边界条件）
   - 无可回收物
   - 最小可回收条件（临界值）
   - 正常数量
   - 大数值边界
   - 单类型多数量
   - 多类型多数量
   - 跨容器/跨类别

3. 选择操作（交互验证）
   - 单选操作
   - 取消选择
   - 数量增减（边界）
   - 批量选择
   - 输入框边界（正常/0/超限/非法）

4. 批量操作（一键操作）
   - 未选择时一键全选
   - 部分选择时一键全选
   - 一键取消
   - 一键后手动调整

5. 回收结果（情况遍历）
   - 部分回收
   - 单类型回收完
   - 部分类型回收
   - 首位/中间/末位回收
   - 翻页后回收
   - 品质遍历
   - 全部回收完

6. 其他操作
   - 返回
   - 关联入口（商店等）
```

## 五、提炼的通用设计模式

### 模式A：临界值验证

适用于：数量限制、解锁条件、触发阈值

| 场景 | 验证点 |
|------|--------|
| 条件 - 1 | 不满足，功能不可用 |
| 条件 = 临界值 | 刚好满足，功能可用 |
| 条件 > 临界值 | 超过，功能正常 |
| 条件 >> 临界值 | 大数值边界 |

### 模式B：输入框边界验证

适用于：数量输入、金额输入、文本输入

| 输入类型 | 预期 |
|----------|------|
| 有效范围内 | 正常 |
| 最小值边界 | 0、1 |
| 最大值边界 | 上限、上限+1 |
| 非法输入 | 负数、小数、特殊字符、空 |

### 模式C：批量操作状态覆盖

适用于：一键全选、批量删除、批量操作

| 前置状态 | 操作 | 验证点 |
|----------|------|--------|
| 无选择 | 批量操作 | 全部生效 |
| 部分选择 | 批量操作 | 覆盖之前选择 |
| 全部选择 | 批量取消 | 全部恢复 |
| 批量后 | 手动调整 | 状态正确更新 |

### 模式D：位置遍历验证

适用于：列表操作、删除操作、移动操作

- 首位操作
- 中间位置操作
- 末位操作
- 翻页后操作

### 模式E：结果池刷新验证

适用于：回收、删除、消耗后的列表更新

- 操作后列表刷新
- 剩余项排序正确
- 空状态显示正确
