## 再次验收先看

1. **历史结论是不通过。** 三通道主迁移链路已有证据，66 条基线为 7 通过、34 部分验证、10 失败、9 环境阻塞、5 未执行、1 依赖阻塞；部分验证不算通过，不把这个历史数量填入新轮次结果。
2. 先读本轮需求并对照 v1.12：通道①已改为常规召集共池、无冷库专属豁免；②③及强转落地不保留专属补救资格。9 月旧文档中的独立名额、补救和申请续接不能继续作为当前规则。
3. 核实本轮客户端、部署服务端、部署配置与平台入口四层身份。历史运行客户端不同于静态客户端；本地 Excel 哈希不能替代部署配置 SHA。三张正式表可读也不代表平台 `cold-server` / `cold-server-target` 已配置。
4. 阶段必须按预告 → D1 → D2 截止前 → D3 已有准备 → 关服 → D5 结束推进。历史环境只能向前拨时，未覆盖前置需要新排期或新环境；不回拨、不恢复更早快照。旧授权、SID、账号和时间增量均不是本轮许可。
5. 重点补验准备页跨 D2 重入、活跃付费口径、可配置携带窗口，以及平台强转、并发/故障恢复、通知和配置生效。不要用 GM 安置、人工推荐标签、加速发车或一次正常完成替代对应业务结论。
6. 可复用的只是 [离线配置快照提取模板](scripts/usage.md)。没有归档可直接执行的 GM、拨时、迁移或账号操作脚本。正常运行台账使用公共 [runtime_acceptance.py](../../scripts/runtime_acceptance.py)，执行顺序与 `next` / `check-advance` / `publish` 按 [运行验收规则](../../references/runtime-acceptance.md)；不复制公共工具。
