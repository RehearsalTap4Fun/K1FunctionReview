# 验收过程文件归档与清理

两类运行验收均在**验收结果已维护到指定文档并回读核验后，自动清理本轮产生且不可复用的过程文件**。按已闭环的需求/反馈项执行，整轮收尾再检查一次；不等待全部需求通过才清理已满足条件的文件。清理不改变验收结论，也不等于恢复游戏前置的 `state.cleanup`。

## 先记录归属，再决定保留

从采集开始记录本轮生成文件的路径、用途与关联需求，放入本轮独立临时目录。协调者负责核对共享引用；协作者只清理自己生成且已完成交接的文件，不能删除其他人的产物。扩展名或位于 `.tmp` 不能证明文件可删。

| 文件情况 | 处理 |
|---|---|
| 已完成归档、无后续依赖的截图/录像上传源、重复导出副本、一次性处理文件 | 满足下述核验后自动删除本地过程副本 |
| 未上传、附件未验证、结果尚未写回、仍需补验/复现或通知核对的材料 | 保留，记录缺口与再次清理的条件 |
| 可复用脚本/模板、用户原始资料、正式报告、计划/状态/进度台账、部署与提交回执、私有配置 | 保留；不属于本规则的删除对象 |
| 仍被报告、经验档案、冻结基线、证据注册表或其他任务引用的原始证据 | 先处理引用；不能安全迁移的最小证据继续保留并说明依赖 |

用户提供的原图和已有文档附件不是本轮临时产物，不因本地清理删除线上附件、历史报告或源资料。可复用方法先合入分功能经验并回读，未完成交接的笔记仍保留。

## 文档核验与证据引用

1. 将本项验收状态、必要说明和实际截图写入正确需求/反馈行，回读文字并逐图打开核对内容、归属和读者访问能力；上传回执、文件名或资源 ID 不能代替实际查看。先前的三语等证据要求继续有效。
2. 保存轻量归档清单：需求/反馈 ID、原本地路径及 SHA256、文档稳定位置/行 ID、附件定位、实际打开核验时间与结果、保留/删除原因。清单放在保留的报告目录，不与待删文件一起删除；不保存凭证或临时签名密钥。
3. 查本轮 plan/state、报告、证据 registry、进度记录、经验档案及已知其他任务的引用。将可迁移的人工文档/报告引用改为已核验的稳定文档附件位置，回读确认仍能找到原图。迁移只改定位，不改观察、原始哈希、结论或冻结的计划/基线；签名下载地址失效时应可从文档定位重新打开。
4. **遵守当前工具的证据合同。** `runtime_acceptance.py` 要求本地证据文件存在，HTML 报告直接引用该文件；`evidence verify` 还核对注册副本哈希。不能把 URL 填入本地 `path`、用链接说明文件冒充原图、删注册项或篡改冻结哈希来通过检查。当前工具无法迁移的机器引用保留其最小本地原件；已确认注册副本完整且上传源不再被其他引用时，可删除重复的上传源。正式报告中的本地链接保持有效，不把“已上传”当成已解除全部依赖。
5. 结果文档、经验与必要证据均可回读，且候选文件没有正在读取/写入、未完成补验、发布或重试依赖后，才进入删除清单。进度播报不等待无关文件清理；用于 `record`、发送结果核对和未知回执恢复的持久证据继续保留。

## 按文件执行并核验

仅对归档清单中明确属于本轮、核验通过的文件执行删除，无需为已确认范围逐文件重复询问。删除前重新解析绝对路径，确认仍位于本轮指定临时目录、未穿过符号链接/目录联接，且内容哈希未变化；文件被他人修改、归属不明或存在共享读取时先保留。

使用当前文件工具或同一个 PowerShell 会话逐文件操作，路径使用 `-LiteralPath`；不按 `*.png` 扫全工作区，不递归清空 `.tmp`、reports、缓存或项目根目录。现有 `cleanup-run-evidence.ps1 Cleanup` 是整目录删除工具，不能用于仍混有正式台账、证据、待处理项的运行目录；本流程不以该命令代替逐文件判定。删除后仅移除已确认属于本轮且确实为空的临时子目录。

回读确认候选文件已删除、保留文件及必要引用仍可用；对仍有机器证据引用的台账执行适用的现有校验，不把校验通过当成线上附件已验证。部分删除失败就记录已删与未删清单、原因和下一步，下次只重试经重新核实的剩余项，不扩大删除范围。

收尾报告简述清理数量、保留原因和归档清单位置。不能为了清空目录删除正式证据，也不能因少量受保护证据仍需保留而跳过其余符合条件的临时文件。
