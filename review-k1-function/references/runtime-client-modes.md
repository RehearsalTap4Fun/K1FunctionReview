# 验收时间节点与客户端路径

功能预检是远端只读静态阶段，不进入本文件的运行流程。运行验收有两个**由用户指定的阶段**：功能验收和版本日验收。现有计划字段 `acceptanceMode` 沿用 `development` / `mainline_regression` 两个 ID，分别对应这两个阶段；ID 不代表一定使用开发分支或主分支，不能按分支名或当前日期替用户选择。完整阶段结论默认需要 **Unity 验收和真机包验收**；用户明确限定为其中一条（包括 Pango 单个快速任务）时只执行该路径，另一条标为本轮范围外：

| 用户指定的时间节点 | Unity 编辑器 | 真机安装包 |
|---|---|---|
| 功能验收 | 按测试用例详细实测 | 按同一用例范围在目标设备实测 |
| 版本日验收 | 通常按玩家体验范围；缺陷/故障、快速任务按测试用例详细实测 | 与 Unity 相同的范围 |

同一阶段所选路径各自记录前置、实际连接目标、断言结果和证据；两条路径都在范围内时可共享已核实相同的需求基线、转换产物和准备方法，不能用一条路径的观察代替另一条。只有本轮所选路径的必要范围都闭环，才能给该范围“通过”结论；单路径结论必须明确路径，不能称整个阶段的双路径验收通过。所选路径尚未执行、缺包、缺环境或只有部分证据时，保留待验或阻塞并继续其他可执行路径。两个运行阶段是不同批次，功能验收结果不能替代版本日结果。

## 每个时间节点的共同前置

以下流程只适用于实际运行验收；静态预检和用户单独委托的建服任务不自动触发客户端转换。运行验收的 `自动刷新配置`、`自动部署服务器` 是独立参数，缺失时默认均开启。关闭只跳过对应的自动操作，不免除本轮产物、版本、目标服和连接验证。跳过准备操作本身不是验收失败；按功能依赖核对现有环境，确实不可用时只记录受影响用例阻塞，继续其他可执行项。

1. 从本轮需求、交接和实际仓库核对客户端与配置分支或提交、所选路径的目标平台或 Unity 项目版本、目标服务器实例/SID、应用类型和设备分配。运行阶段可安全切换目标分支：先核对用户指定工程的 Git 状态和当前 Editor 路径；工作区有改动时保留原状，使用与指定工程对应的隔离工作树准备目标版本，不把未打开 Editor 或当前分支不同直接当成终局阻塞。Editor 未打开时按指定工程路径启动，再核对实际项目和提交。未知的必要目标先查后问，不猜测分支或占用他人服务器。
2. **按 `自动刷新配置` 准备配置表和多语言。** 开启时，客户端 Jenkins 优先用 `K1_Build_Config_I18N_Mac`，显式传入本轮 `Client_Branch`、`Config_Branch`，同时设置 `Config=true`、`I18N=true`。该任务不可用或不适用于本轮时，核对参数和产物后再选 `K1_Build_Config_I18N` / `K1_Build_Config_I18N_v2`。`K1_Build_Config_I18N_Mac_Internal` 只供内部自动修复流程调用，不作为常规验收入口。关闭时不得启动配置表或多语言转换；复用现有产物，核对本功能所需配置字段、值及客户端实际加载情况。只有证据表明现有产物不适用，才阻塞依赖该配置的用例。两条路径输入、版本和产物完全一致时可共用回执；不一致时分别转换并记录对应关系。开启刷新时版本日须使用本阶段的新转换回执，不能拿功能验收的旧回执代替。
3. 刷新开启时等待转换任务终态成功，核对构建号、实际输入分支/提交、日志与产物或发布位置；关闭时记录所复用产物的相同证据与版本核对结果。产物存在不代表目标客户端已加载；失败、取消、产物不明或输入不符时先定位影响，不直接开始受影响路径的验收。重试或切换任务前核对是否已有写入，避免重复推送或覆盖产物。
4. **按 `自动部署服务器` 准备目标服。** 开启时按 [设备与测试服隔离](device-server-isolation.md) 确认分配，并按 [Jenkins 环境准备](jenkins-test-environment.md) 执行已授权的备份、导入和部署。关闭时不得自动部署或重建；核对已指定或已分配的现有实例是否具备本功能所需服务能力、配置和开关，服务器分支名不同不能单独证明不适用。若无法确认，先查实际提交、运行配置和可安全读取的开关状态；有适用实例则继续验收，确无适用实例才阻塞依赖该服的用例，不记业务失败。两种情况都须核对服务器就绪、代码/配置版本、实例身份和 SID，并确认所选配置产物在客户端及运行环境生效。默认每个客户端实例独占服务器；共享例外只按隔离规则处理。同轮续跑且输入版本未变时，可经复核沿用有效实例。
5. 让所选路径的客户端分别登录各自专属服，核对玩家、SID、客户端/服务器/配置版本及多语言资源；将转换、部署和所选路径的登录证据保存到本轮环境记录。转换与部署就绪只满足前置条件，不代表业务验收通过。

配置/多语言**转换任务**与玩家可见界面的英、俄、阿**实际显示检查**是两步；转换成功不能替代各路径必要的切换语言、截图和界面断言。

## Unity 路径

在对应版本 Unity 项目中确认已加载本轮转换产物与多语言资源，进入 Play 模式并登录本路径专属服。记录项目/客户端版本、资源版本、Unity 实例和实际登录目标，按本节点范围执行断言。Unity 观察不能证明真机触控、安全区或原生 SDK 表现；这些结论由真机路径提供证据。

## 真机包路径

按目标平台构建真实设备安装包，确认包使用本轮转换结果。目标平台有适用的 Mac 出包任务时优先使用，例如 Android 的 `K1_Android_Build_FromMac`；先核对现行任务参数、渠道和产物，其他平台按实际可用任务选择。Android 依照 [Mac 出包通知、APK 下载与真机安装](android-package-install.md) 核对 Jenkins、钉钉通知、下载文件、ADB 安装和实际登录目标；记录包构建号、客户端版本、渠道与安装设备，按本节点范围执行断言并保留触控、安全区、原生 SDK 等适用证据。
