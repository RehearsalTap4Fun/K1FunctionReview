# 版本日未通过项修复工作流

这是**版本日验收结束后的独立修复任务**。用户要求收集未通过项并修复时启动；不属于功能预检、功能验收或版本日验收的内部步骤。建单与修复不会自动改变原验收结论；修复后的 Unity 验证另留本轮结果。

## 1. 收齐当前未通过项

1. 先确定用户指定的版本日文档、版本/页签和读取时间。未给链接时按 [版本进包表来源](acceptance-progress.md#版本清单与统一台账) 查当前任务与已确认交接；仍有多个候选时确认目标，不混合不同版本日。完整读取分页、隐藏行及筛选外数据，以源文档当前的验收状态 `未通过` 精确筛选。`验收中`、`待验收`、阻塞和仅在旧报告中失败但源表已改为其他状态的项不纳入本次清单。
2. 按稳定行 ID / 原 Jira ID 去重，保存每项原行链接、状态、需求、失败详情、反馈表 ID 与原图、运行报告、客户端/服务器/配置版本和已知复现条件。逐项核对在线原图与预期图；无证据或归因未定时标记待核，不编造复现。保存读取时的完整 `未通过` 数量及逐项处置：入单、已有关联 Bug、待证据、非本轮工种等，不能静默漏项。
3. 查询 Jira 是否已有覆盖同一问题且仍有效的 Bug，避免重复。一个源行可能含多个独立问题；一处问题也可能关联多行。保留源行 ↔ 问题的映射，不把需求行数当缺陷数。

当前源文档没有 `未通过` 项时，记录零项和来源快照即可结束，不创建空 Bug，也不启动修复或 Unity 复验。

## 2. 提交汇总 Bug 并分工

用户启动本工作流即授权为本批未通过项**建立一张汇总 Bug 单**。用已注册的 `$jira-bug-creator` 按 NK 要求准备、校验、提交并回读；Bug 单标题标明版本日和修复范围，正文逐项列原需求/Jira、问题编号、复现步骤、预期与实际、证据、影响版本及当前归属。已有有效 Bug 则在汇总单中关联，不重复创建同一缺陷；提交结果未知先查 Jira，不能盲目重提。证据不足的项目仍列在汇总与待补清单中，不写成已证实缺陷。

对每个问题明确标注 `客户端`、`服务器` 或 `归属待核`，写明判断依据、目标仓库/分支、修复负责人或交接对象；混合原因拆成可核验的子项。Jira 必填的修复/影响版本、优先级、Bug 等级、部门、经办人与复现率以当前来源核实；汇总单只能设置一个主经办人时，其他工种的具体负责人写在子项/交接中，不能借主经办人推定全部问题都归其工种。无法核实的必填事实先补证或询问，不猜填。

## 3. 只修指定工种的问题

从用户本轮明确指定的客户端、服务器工种及其目标工程/分支确定修复边界；缺少指定时先完成只读收集、归属和 Bug 草稿，待工种明确后再改代码。只在对应仓库和隔离分支处理该工种的问题，先检查工作区与目标提交，保留已有改动。客户端只改客户端问题，服务器只改服务器问题；跨端缺陷须分别列出各端改动和负责人，未指定的一端保持待交接。配置/策划文档问题另列，不因选择客户端或服务器而擅改正式配表或原文档。

对每项记录修改文件、提交/构建版本、解决的源行及 Bug 子项，运行针对性编译或检查，复核无关功能影响。尚未修复、未能复现或缺权限的项目保持开放，不用“代码已改”代替运行验证。不要在本任务内发布线上热更，也不要覆盖他人测试服。

## 4. 修复后启动 Unity 定向复验

只对已完成且可部署的修复项启动复验。按 [验收节点与客户端路径](runtime-client-modes.md#每个时间节点的共同前置) 在本轮目标客户端/配置分支优先运行 Mac 配置表与多语言转换任务，按 [设备与测试服隔离](device-server-isolation.md) 部署或核对本轮专属服务器；服务端修复必须确认实际运行的是修复提交。转换与部署的任务、分支、构建号和实际产物均留回执。已有适用产物/实例是否可复用按本轮明确参数与实际版本核对，不用历史验收回执冒充本轮修复版本。

打开或启动用户指定工程的 Unity Editor，核对项目、客户端提交、配置/语言资源、服务器提交、SID 与角色，进入 Play 并连接专属服。按每个 Bug 子项的原复现步骤和原图执行定向验证，覆盖受修复影响的邻近路径及适用的 ESC 返回/HUD 状态；语言显示检查按 [语言影响规则](ui-language-and-screen-adaptation.md) 判定范围。记录修复前后观察、截图/日志、通过/未通过/阻塞以及尚未执行的真机路径。Unity 通过只表示本次 Unity 定向复验通过，不能替代真机复验或宣称整版验收通过。

逐项回写汇总 Bug 的验证结果与证据。需要同步版本日原表或反馈表时，按 [在线状态规则](acceptance-progress.md#版本清单与统一台账) 与 [反馈文档规则](feedback-document.md) 核对行身份、归属、状态并回读；不能因创建 Bug 或提交代码就把 `未通过` 改为 `已完成`。剩余未通过项、跨端待交接、真机缺口及下一步单独交付。
