# 按功能沉淀和复用验收经验

适用：需求对齐、静态预审、运行验收、反馈复验及中断续验。调用 Skill 的 Agent 在本次任务中执行读取与更新；不是后台任务，也不是现有 CLI 自动生成业务经验。经验帮助定位与执行，需求仍以本轮对齐文档为准，验收结论仍由本轮证据及原发布合同决定。

## 文件约定

所有下列路径相对 Skill 根目录解析，安装目录是链接时写入其实际源目录。

按功能建目录，同一功能的经验、脚本与脚本使用说明放在一起：

```text
features/
  index.md
  k1-gold-miner/
    experience.md
    scripts/
      usage.md
      gold-miner-advance.cs.txt
      gold-miner-visible-input.cs.txt
```

后续功能使用 `features/<featureId>/`；没有运行脚本时不创建空脚本目录。通用读写规则、档案模板和跨功能公共工具仍留在原通用位置。

| 内容 | 位置 | 维护方式 |
|---|---|---|
| 功能索引 | [features/index.md](../features/index.md) | featureId、名称、别名、关联需求/分支、档案链接、更新时间 |
| 功能档案 | `features/<featureId>/experience.md` | 一个功能一个稳定 ID；新版本追加适用范围，不按验收批次重复建档 |
| 档案模板 | [../assets/feature-experience-template.md](../assets/feature-experience-template.md) | 首次验收该功能时按实际材料填写；未知项明确记录 |
| 功能运行脚本 | `features/<featureId>/scripts/`，使用说明为该目录的 `usage.md` | 档案引用唯一维护源；说明登记参数、依赖、清理方式和验证边界。既有跨功能公共脚本仍引用根目录 `scripts/` |
| 本轮增量与恢复笔记 | `FunctionPreview/.tmp/<run-id>/experience-notes.md` | 记录读到的档案版本/哈希、采用或弃用的条目、新事实、回写结果及恢复动作 |
| 原始证据 | 本轮 `.tmp` 或 `reports` | 不随 Skill 分发；档案保存可定位来源及必要的非敏感摘要 |

`featureId` 使用稳定的项目与功能名，如 `k1-gold-miner`；改名只增补别名。Jira、活动实例、分支和验收批次是关联信息，不作为唯一功能 ID。后续迁移在线文档时沿用 featureId，将在线档案地址登记在同一档案；当前以本地文件为维护源，不建立未请求的在线同步。

## 验收前自动读取

1. 读取功能索引，按功能名、别名、关联需求或分支匹配；只加载本次相关档案及需要的脚本说明。多项命中先用需求和现有材料辨认功能，仍有歧义才询问用户。未命中时查索引中的已知别名及本次来源，确认是新功能后按模板建档并注册索引，不能套用相似功能的经验。
2. 读取档案的适用版本、来源、待验证/已失效条目及脚本清单。把本轮 featureId、档案路径和读取时的文件哈希、采用/待复核条目写入 `experience-notes.md`。没有现成 run-id 时，沿原工作流创建运行目录。
3. 运行验收先按下述文档确认标记核对来源及版本；一致时沿用已确认需求，不重复全量对齐。对比当前文档、三端实际版本、配置、入口签名与界面生命周期，按受影响条目决定复用：兼容且有依据的可复用定位与操作方法；受影响、版本未知或证据不可读的先复核。版本不同不等于全部失效，版本相同也不代表身份、授权和当前价格相同。
4. 将历史易漏场景合入本轮需求/用例核对。经验不增加未经确认的需求，不跳过原图查看、需求对齐、实时版本解析、正常业务证据或收尾检查。历史通过及历史问题状态均不直接填入本轮验收结果。
5. 独立准备环境任务只读已明确关联功能的环境经验及通用环境参考；不强制建立虚构的功能档案。经验里的历史账号、SID、GM 范围、商品和配额不是本轮授权。

运行经验记录设备独占实例的核验方法、共享依赖与服务器级 GM 的影响范围；具体分配和权限每轮重核，不继承历史许可。结果写回后按 [过程文件归档与清理](runtime-artifact-cleanup.md) 维护稳定文档附件位置；删除本轮临时文件前更新可迁移的经验引用，仍有机器校验/补验依赖的证据保留并说明原因，不能留下失效路径。

## 预检后文档确认标记

本功能经验档案的“再次验收先看”之后固定保存 `documentBaseline`。首次预检结束且文档确认、原文维护和回读均已完成时写入；无差异也需要实际同版本回读。实现尚有缺陷不妨碍记录文档确认，但该标记不代表实现或运行验收已通过。

| 字段 | 含义 |
|---|---|
| status | `precheck_confirmed`（预检后文档已确认）或 `needs_review`（待复核）；未知和历史空档案默认待复核 |
| source | 原文档唯一来源/链接，不能只写功能名 |
| confirmedVersion | 已确认的稳定版本号或内容哈希；时间戳、相同链接不能单独证明内容相同 |
| confirmedAt / precheckRunId | 实际确认时间及时区、对应预检批次；批次关联预检报告、对齐记录和冻结三端版本 |
| currentVersion / checkedAt | 本次读取到的版本/哈希及核对时间；与 confirmedVersion 使用同一种标识 |
| evidence | 预检确认、原文回读及本次版本核对的真实证据定位；运行计划中使用 kind/path 条目 |
| reason / nextAction | 待复核原因、受影响需求及下一步；已确认时可留空 |

后续验收读取原来源并与标记比较：

- 相同来源且版本/内容哈希一致：保留原确认时间和批次，更新本次核对记录；在计划和报告明确“当前文档已是预检确认后的版本”，直接使用，不重复完整对齐。
- 内容变化：将旧标记保留为历史，当前状态记待复核，只重新对齐受影响规则并校准相关用例；完成确认和回读后更新当前标记，关联原预检批次与本次增量对齐证据。
- 来源不可读、依据缺失或版本标识不可比：记待复核及实际原因，不宣称仍是最新。可以继续不依赖未决规则的独立验证；文档待复核时不能给完整通过结论。旧档案只在取得证据后补标，不能批量推断“已确认”。

此标记证明文档基线，不能用来沿用旧代码、配置或运行结果；三端版本变化仍核验当前部署和影响范围。静态报告发布后需单独写入并回读功能经验档案，renderer 不会代为回写。

## 反馈来源与维护交接

两类运行验收按 [反馈文档规则](feedback-document.md) 保存真实链接、工作表身份、适用功能/版本、字段映射、最近回读和待维护事项。这些来源交接属于私有运行数据，放在本轮 `.tmp` / `reports` 的笔记与交接或使用者已有的私有功能档案，不写入共享 Skill。记录缺链接时用户选择补链接或新建的决定及适用范围，已创建的表供协作者和后续批次复用。下次先核对来源/字段/权限，不重复问可查事实，不因旧链接不可访问就另建重复表。

## 每阶段和中断前自动更新

需求对齐、静态预审、一个运行场景/阶段结束、版本变化、交接或中断前，先保存原始证据及本轮增量；有新增内容时立即合入档案，不等待整轮验收通过。异常终止来不及整理时，续验先读取本轮笔记和台账，补回尚未归档的增量。

每条经验使用稳定 `entryId`，包含：**结论/方法、状态、适用条件或版本、验证方法与日期、来源编号、下次操作**。已验证的方法记录入口/参数/成功信号；仅发现现象、尚无根因的条目分开写。条目可按表格分组，共用的日期与来源需在组首明确。

| 状态 | 含义与更新规则 |
|---|---|
| 已验证 | 在记录的范围内有实际证据；静态核对、编译、运行和业务结果分别说明。历史验证时间不因整理文档而刷新。 |
| 待验证 | 线索、缺少关键条件、与新事实冲突或适用性待复核。写出缺口和具体复核动作，不能当成可靠运行步骤。 |
| 已失效 | 有证据说明在指定版本/条件下不可用。保留旧方法、原因、失效范围和替代条目；旧版仍适用时另行注明。 |

合并时按“同功能 + 同方法/问题 + 适用条件”去重；复用成功更新该条目的最后验证日期和新来源，不重复追加整段日志。不同版本观察有冲突时保留两份依据，将受影响的新版本适用性记为待验证；查明失效后再标已失效。没有看到旧入口只说明该入口需复核，不等同于功能业务失败。

更新既有条目前，按具体页面、方法或问题身份确认 entryId；只有“领奖入口”等泛称、存在多个候选且现有证据无法区分时，先保存一条待定位线索和补证动作，不擅自改变某个候选条目的状态。

写入前复读档案与索引；若读取后有其他修改，基于最新内容合并自己的增量，保留他人条目和引用。原始材料与已有独有经验不得因整理丢失。写后回读条目、链接和索引，在笔记记录“已更新 / 无新增 / 待回写”及影响的 entryId；只有确实回写成功才报告已沉淀。

安装位置不可写时，将拟合并内容、目标文件、失败原因保存在本轮笔记并继续可执行验收；交付明确档案待回写，不另建未登记的第二维护源。无新增时记“无新增”即可，不为完成步骤生成重复内容。

## 来源和留存

每条经验关联来源编号；来源表包含日期、文档版本/冻结 SHA/运行批次、文件或在线定位、验证层级和可访问情况。可以在档案中保存小段必要的结论摘要，不复制完整回执、账号快照、密钥或 DownKey。

本地来源用明确的 `FunctionPreview/.tmp/...` 或 `FunctionPreview/reports/...` 路径标识，并注明不随包分发；用户文档使用实际已读到的稳定地址。不要猜测未知链接。需要长期保留的非敏感证据可随本轮报告放入唯一的新 reports 目录，不改写旧报告。

证据不在接收者机器或已清理时标“来源不可访问”；历史记录保留，当前可复用性待复核。档案整理不代表重新运行验证，摘要不能冒充原始证据。优先读取已归档方法，只有受影响步骤才回查相关源码或日志，避免每轮扫描全部历史报告。

## 必要运行脚本一起存档

首次走通且后续会重复使用的探针、导航或输入辅助，保存为去除本轮绑定值的模板；已有模板直接引用，不复制第二份。一次性实验、带凭证/固定账号的执行副本仍留本轮目录。脚本说明至少包含：

- 稳定 scriptId、相对文件路径、用途、原始来源、当前文件 SHA256；脚本内容变更同步更新哈希及变更原因。
- 宿主/调用入口、依赖类型和版本、全部必填参数及单位、开始状态、正常完成信号、停止/清理方法、失败恢复动作。
- 会产生的请求、资产消耗或文件写入；按本轮授权绑定账号、SID、活动、上限和保留库存，不保留历史许可。
- 实际验证日期、精确脚本版本（能确认时记录哈希）、证据和覆盖范围；“模板保存”“编译通过”“实际执行”“业务验收”分开。没有历史哈希时明确当前模板未逐字重跑，不能把旧验证绑定到新文件。

使用前读脚本说明并检查依赖；复制到本轮 `.tmp` 后替换参数，确认没有未替换标记，再按宿主的调用方式执行。未知结果先回读，资产类操作不盲目重试。版本检查失败时复核受影响代码和接口，不能只填入新版本号绕过检查。执行后保存回执并确认回调/探针已注销。

## 交付

在原验收结论和报告之外，简述本轮读取的功能档案、新增/修订/失效条目、脚本变更及待回写项。档案维护与业务验收状态分开；失败或有阻塞的验收同样可以沉淀有证据的经验。
