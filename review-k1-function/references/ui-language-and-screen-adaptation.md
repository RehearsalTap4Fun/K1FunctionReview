# UI 多语言与屏幕适配验收

适用于本轮需求新增或改变玩家可见界面、文案、弹窗、入口、图标位置或交互区域时。静态预审只检查实现依据；通过结论必须来自目标构建在实际支持的设备与语言上的运行证据。功能没有玩家可见 UI 时记录不适用原因。

按 [验收模式](runtime-acceptance.md#1-接续依据与权限) 确定范围：下述组合矩阵适用于开发分支详细验收或用户明确要求的语言/适配专项。主分支回归按本轮正常玩家体验所用的语言和设备检查显示与交互，不自动扩展组合矩阵，也不将单一组合体验通过外推为全部适配通过。

## 选取覆盖组合

- 先核对产品当前支持的语言、设备与方向范围。多语言验证主要覆盖**俄语、阿拉伯语和英语**：俄语检查长文本，阿拉伯语检查 RTL 与混合方向，英语作为常规排版基线。需求明确指定其他语言时再补测该语言；某种目标语言或测试账号不可用时记录缺口，不把其他语言通过外推为全部通过。
- 选取受支持的较窄/较小屏、常规屏、较宽或较高屏；产品支持平板或横屏时纳入相应端点。记录设备型号、系统、原生分辨率、显示缩放或安全区信息，以及客户端构建号。模拟分辨率可以补充定位，不能代替需要真机验证的触控与安全区结论。
- 用有代表性的组合覆盖语言与屏幕端点；至少让英语跑通主要尺寸，并让俄语和阿拉伯语覆盖空间最紧的关键界面。高风险弹窗、动态文本或方向变化再补充组合，不要求无意义地穷举全部笛卡尔积。

## 多语言断言

对改动路径及相邻状态检查入口、正文、按钮、提示、空/错状态、奖励与数值。核对翻译含义、缺失键或回退、残留其他语言、字体字形、截断与换行；用户名、联盟名、时间、货币、计数等动态变量应完整且顺序正确。文本切换、语言热切换和重新登录后分别核对当前显示；可在原文/译文间切换的控件要往返验证。RTL 界面还要检查阅读顺序、镜像方向、嵌入拉丁文字和数字、图标与按钮对应关系。

## 屏幕适配断言

在选定尺寸上逐一查看首屏、列表滚动末端、弹窗、长文本、输入法弹出、横竖屏切换（仅适用时）和异常/空状态。确认安全区与刘海/圆角不遮挡内容，文字、数值和图标不重叠、不越界，关键操作可见且可触达；滚动、点击命中区、缩放与返回路径正常。截图以设备实际像素保存，必要时附连续帧证明闪烁或瞬态问题。

## 证据与判定

每个断言记录语言、设备/分辨率、版本、前置条件、实际步骤与结果；问题附原尺寸截图及期望/实际差异。静态键值存在、单一语言或单一分辨率正常，只能证明已覆盖的组合。把未执行组合标为待补验或真实阻塞，不能写成通过；同一缺陷影响多个组合时保留对应证据并按唯一缺陷计数。涉及删除、转让或付费的界面可以停在确认弹窗验证排版，不为适配测试执行不可逆确认。
