# 已学习流程的复用

用于同一功能中已实际走通的重复操作；与语义录制/回放共用本轮身份、版本、授权和证据台账。

先按 [功能索引](../features/index.md) 读取对应档案，并执行 [经验读写规则](feature-experience.md)。本页只保留跨功能的重复操作原则；新经验更新对应功能档案，必要脚本归档并登记使用说明。

## 学一次，后续按状态执行

- 首次成功时记录业务名、起止界面、语义入口/控件、异步完成条件、权限与资源参数、异常分支、版本和成功回执；不只保存屏幕坐标。
- 重复操作先查已有流程。客户端入口及界面结构仍兼容、身份及活动匹配时直接复用，不每次截图、重新找类名或重读同一源码。配置更新重新确认受影响参数，不能沿用旧价格、数量与目标。
- 导航检查页面生命周期；业务动作核对 Ack、适用的 Ntf、权威状态及资产差值。结果未知时只回读，不自动再次购买、升级、领奖或开始新局。
- 将同一流程的异步等待交给有时限的 MCP 状态机，不让模型在每个确定步骤之间重新决策。结束、身份/活动切换、编译重载、异常或超时都注销回调。
- 截图可后台采集，无需逐张分析。首次页面/结果、新元素/布局、异常、视觉断言及报告关键节点仍需实际看图；未知弹窗或结果矛盾时退回视觉检查。反馈表原问题图仍必须逐项查看。
- Android 真机普通点击优先使用 `adb -s <serial> shell input tap <x> <y>`，由 Android 输入系统向已确认设备注入单点触摸。先核对 `adb devices -l` 的目标序列号、当前截图的分辨率/方向及可见控件，再取其中心附近坐标；点击后以页面变化、回包或权威状态确认命中。ADB 命令成功仅证明输入已发送，不证明控件或业务动作成功；直接调用 UI 回调、GM 或业务 Req 不算这一步的玩家点击证据。
- Unity Editor 中，部分控件（例如地图宫格、页签）直接对目标发 `ExecuteEvents.pointerClick` 不会触发，因为它们依赖按下/抬起事件，或者点击处理器在父节点上。这时按玩家点击的方式走一遍：先用 `WorldToScreenPoint` 取控件中心的屏幕坐标，用 `EventSystem.RaycastAll` 取命中的最上层对象，再沿层级依次发 pointerDown、pointerUp、pointerClick（`ExecuteHierarchy` / `GetEventHandler`）。这种射线点击还能顺带证明控件没被遮挡、真实可点。点击后同样要以界面栈变化、回包或权威状态确认命中；反射调用 UI 回调不算玩家点击证据。
- Android 真机截图优先用 `adb exec-out screencap -p > <本地绝对路径>.png`，直接保存到电脑。不要先 `adb shell screencap` 写入手机再 `adb pull`。记录耗时须区分 ADB 命令、游戏等待、文件传输与看图；单次 3–5 秒的命令时长不能直接归因于截图编码。
- 已确认坐标和前置的连续点击可在一次执行中顺序完成，按业务状态等待，并只在关键状态采图；未知弹窗、账号/语言切换、资源消耗、异常及视觉断言仍先看图再继续。避免每次点击都启动新命令、固定等待并查看图片。批量脚本遇到状态偏离即停止，不盲点后续坐标。
- 需要连续观察动画或瞬时界面时，若环境已有 `scrcpy`，可使用常驻画面流观察；报告证据仍另存原始截图或录屏并核对版本、角色与触发步骤。没有 `scrcpy` 时沿用 `adb exec-out screencap -p` 或录屏，不为提速把工具安装当成验收前置。
- 流程不是授权缓存：购买逐次核对商品、当前展示价格、数量、限购和支付环境；GM 以本轮许可为准，旧 GM 授权不能带进正常玩家体验。
- 固定导航与游戏策略分开：下一关入口可复用，瞄准、障碍布局和道具选择仍依据当局可见信息，不能把旧角度套到新关卡。
- 记录调用次数、成功/超时/回退次数及耗时；只有实测数据才能声称提速。
- 已确认 API 记录签名、所属类型和可读 UI 文本组件，后续先用记录；不要对同一个已验证方法反复全文搜索。新 API 先确认字段/方法与参数类型，编译失败时保持关卡未开始或通过正常说明页暂停，不能边空耗倒计时边补工具。

## Unity 首次导入与独立实例接入（2026-11-11）

- entryId：`windows-fresh-unity-import-mcp-route-20261111`；状态：已验证的环境操作方法；适用：Windows、Unity 2022.3.62f2c1、项目集成 TFW unity-mcp v10.1.1-beta.1 的此次验证版本。不是功能验收通过记录。
- 全新 Library 的首次导入可在脚本编译成功后继续处理音频、预制体及 Spine 后处理。短时没有新增导入行、低 CPU 或没有 MCP 端口不足以证明导入失败；结合新资源路径、后处理日志与最终正常退出回执判断，不按累计耗时重建缓存。
- 项目本版 MCP 自动接入处理器默认跳过 batch。`-batchmode -quit` 应以明确成功退出和退出码 0 核验；交互 Editor 另核真实项目路径、编译状态和实例。进 Play 后首次 SpriteAtlas 打包仍可能暂时阻塞调试读取，读取失败不重发业务写操作。
- 交互实例未自动连上已有 MCP 服务、但独立调试桥已可用时，本版可由目标 Editor 调用 `MCPForUnity.Editor.Services.MCPServiceLocator.Bridge.StartAsync()`。返回只记录请求排队/完成标量，不序列化 Task；随后重新枚举实例并按新项目的完整 `Name@hash` 固定路由，再读取状态与自定义工具。两个项目同名时尤其不能仅凭名称选择。
- 登录框架错误的 Editor 弹窗可能共用“玩家在线”的泛化文案。先保留原错误、核实际 errCode 和服务端对应记录，再判断是否在线；弹窗文字本身不构成强制登录的依据。正常重连成功也不能抹掉首轮错误或潜在补创角副作用。
- 下次复用先核工具包版本、进程、项目、初始化阶段和实际回执；账号、服务器、GM 许可与当前数据不从本条经验继承。具体环境与原始回执保存在使用者私有任务笔记，不写入共享 Skill。

## 钉钉反馈单元格多图保留（2026-11-11）

- entryId：`dws-axls-multiple-images-preserve-20261111`；适用范围：本批次DWS CLI实际返回的schema与axls表格，复用前须重新查支持能力。
- `sheet write-image` 在本次实测中替换目标单元格已有图片，不是追加。先完整读取该单元格所有图及文本，保留原resourceId/resourceUrl；有其他协作者变化时重新合并，不盲写。
- 本版 `dws schema --cli-path 'sheet range update' --compact` 明确支持 `type:richText`、`texts`内image子项；`resourceId`单独不足，必须提供真实`resourceUrl`。这是live schema证明的新格式，不是顶层`type:image`。本次先media-upload真实本地图片，随后一次写入含全部图片的richText，再完整回读D2；不要把此方法用于尚不支持该格式的旧CLI。
- 多图写入成功后仍逐图核验：通过文档真实resourceId调用 `doc +media-preview` 下载，实际打开，并核下载字节与原图SHA一致。相对resourceUrl不能作为群消息HTTPS图片链接；播报另取真实临时downloadUrl，签名链接只保留私有台账。
- 本次两张真实英俄失败图片同时回读与逐图打开成功；不能仅凭write响应或图片数量声称原图已保留、附件可用。
