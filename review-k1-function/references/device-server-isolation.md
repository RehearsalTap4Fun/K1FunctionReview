# 验收设备与测试服隔离

用户指定的功能开发完成时与版本日两个节点，都要分别执行真机包和 Unity 验收；默认**每台真机设备或 Unity 客户端实例对应一个独占测试服实例**。独占的是本轮使用的服务器实例及其可变状态，不要求独立物理宿主。每轮实际验收须在配置表与多语言转换成功后启动本轮专属服务器；接续同一轮时可沿用本轮已启动且仍满足授权、版本和隔离条件的实例。只读文档、静态预检和排程不要求部署服务器。

## 开测前分配与确认

先查本轮用户指定参数、已有交接和可核实的部署回执，再由协调者保存分配表。新增设备、换服、重部署或接续时核对实际绑定，不能只凭旧表认定仍独占。

| 设备 / 客户端实例 | 协作者 / 账号 | 环境 / 宿主 / 实例 / app / SID | 实际代码与配置版本 | 独占与跨服依赖核验 | 分配 / 部署授权出处 |
|---|---|---|---|---|---|

实例身份不能只写 SID；同一 Jenkins 用户的同 SID 部署可能重建同一实例。不同账号、设备名、入口别名或容器名，也不能单独证明服务器时间、活动和存储已隔离。核对当前使用者、实际登录目标及其他设备绑定，记录共享的战场服、跨服活动、时钟、数据存储和全局服务。

必要参数包括目标实例/SID及设备分配、代码与配表分支/版本、适用的 app、生命周期；需要复制数据时另核对来源 SID、导入/重建范围和已授权的数据保留方式。能查到的事实先查，已确认仍适用的参数和授权不重问。无法确定的分配、部署或数据范围向用户逐项确认，每次只问一个缺口并给出推荐值或选项；不猜测 SID、不沿用他人的实例，也不要求粘贴凭证。

必要分配、参数或授权未明确前，可以继续读文档、只读查环境和编排计划；受影响设备暂不部署或执行游戏操作。其他已经完成隔离核验的设备可继续其独立验收。仅提供需求、分支或“开始验收”，不能替代缺失的服务器分配与部署范围。

## 复用、部署与就绪

完成本轮配置表与多语言转换后，按 [Jenkins 环境准备](jenkins-test-environment.md) 在已确认范围内启动本轮专属实例；接续同一轮时先核验本轮实例，仍满足版本和隔离条件即可沿用，不因每次补验重建。每台设备使用自己的工作流运行目录和明确目标，不共用部署回执；同一来源 SID 的备份仍按原工作流的唯一关联规则协调，目标服不同不代表可以并发备份同一来源。

“本人同 SID”默认值只适用于已确认的单个目标，不能为多台设备反复套用后声称隔离。实例占用或范围冲突先停止受影响部署并解决分配，不覆盖他人实例，不自行换 SID。构建成功后回读实际实例、版本、存储范围、时钟与依赖，再让对应客户端登录并核验实际玩家/SID；部署就绪不代表功能验收通过。

将分配表和实际就绪证据作为运行清单的一部分，通过现有 `state.environmentEvidence` 引用本地证据文件。计划 `executionGroups.resources` 使用统一的实际实例/时钟/跨服依赖标识及 read/write 权限；没有新增 JSON 字段或自动全局锁。

## 服务器级 GM 与同服例外

执行 GM 前核实其真实作用域：角色、整服、战场、跨服或整个环境；不能凭命令名判断。改时间、活动强制开启/结算、重启、清档及数据导入等可能影响整服或依赖服务。即使游戏服不同，共享战场、时钟或存储仍按共享资源处理；未确认影响范围时不执行该操作。

只有用户明确指定同服验收时才采用例外，记录决定、共享参与者、受影响用例和执行顺序；不把资源不足或等待部署当作默认例外。服务器级 GM 由协调者统一安排，在原授权范围内确认所有受影响协作者已停在安全节点、保存必要证据且没有仍需当前状态的断言后，由指定一人执行。推进时间还需执行原运行规则的 `check-advance`；该脚本只检查当前台账，不能代替其他设备/台账的核对。操作后回读共享状态再交接恢复，协作者不能各自执行服务器级 GM。

跨服功能确需联动时，同样在计划里显式列出共享拓扑与顺序；独占服不能消除业务上的共享影响。仍有覆盖窗口冲突时先完成受影响验收或准备独立条件，不以共享例外擅自放弃验收项。

## 收尾与经验

记录各设备最终服务器/账号、代码与配置版本、游戏时间、共享状态变化、实例到期时间和后续使用者。临时文件清理不包含销毁测试服、删库或清档；这些操作继续按原授权范围处理。可复用的部署方法和隔离检查点写入分功能经验，历史分配和授权不能自动作为下一轮许可。
