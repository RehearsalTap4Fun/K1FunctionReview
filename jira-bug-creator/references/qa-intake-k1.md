# QA 问题输入整理（K1 / NK）

此规则提炼自团队 QA 提供的 `jira-bug-creator` 包，供 K1 的一句话描述与截图建单使用。原包的 X2 默认项目、旧版本号、负责人缓存和自动学习记录不能直接套到 NK。

1. 先从用户描述和原始截图提取可观察事实：功能入口、操作前状态、操作步骤、实际表现、包体版本、服、账号、语言和复现频率。截图没有证明的预期或步骤标为待确认，不从图片示例值推定规则。
2. 用户明确写了 `【功能名】` 时保持原文，标题只补问题现象，避免脚本再次添加功能前缀。没有明确功能名时按当前需求文档或 Jira 已确认名称选取，不沿用旧包的 X2 特殊功能映射。
3. 区分 Bug 等级（A–D）与 Jira 优先级（如“一般”“高”）：它们是两个字段。等级可参考问题影响，但不凭关键词把优先级自动设成“非常高”。提交 JSON 必须显式给 `bug_level` 和 `priority`；不确定时查当前 Jira 选项并向用户确认。
4. 用户指定的经办人优先。仅当用户没有指定时，才从当前 NK 需求单、负责人或团队信息中确认；历史缓存和脚本猜测只能做候选，不能覆盖明确指派。
5. 建单前检查修复版本、影响版本、复现步骤与附件原文件。将事实和根因猜测分开；附件涉及凭证或个人信息时先处理。建单后回读字段和附件，核对经办人是否被 Jira 自动化改写。

发现问题或填写反馈表本身不代表用户授权创建 Jira 单；由用户明确提出“提 Bug”后才提交。
